# WB 灰度统计工具

一个面向 Windows 的 Western Blot（WB）条带灰度分析工具。PySide6 桌面界面 + 原生位深定量核心：16 位 TIFF 不降位深直接定量，ROI 泳道划分、强度剖面质控、内参归一化与 fold change 一步完成，导出的展示图带着一份可直接抄进方法学的处理记录。

> 当前版本仍建议由实验人员复核结果；曝光饱和、强噪声或背景极不均匀的图片可能需要调整参数、旋转，或改用 ROI 半自动路径。软件查得出什么、查不出什么，见「已知限制」一节——那一节请务必读完。

## ⚠ 适用范围（先看这一节）

**本工具适用于线性响应的化学发光 / 荧光成像**——ChemiDoc、Amersham ImageQuant、Odyssey 等 CCD/CMOS 成像仪导出的 TIFF。这类设备的像素值与光子数近似成正比，所以"把扣完背景的像素值直接累加"得到的积分灰度与蛋白量成正比。

**X 光胶片的扫描图不适用。** 胶片的响应是对数的（光密度 OD 与曝光量成对数关系），直接做线性积分会系统性压缩浓度差：真实的 2 倍梯度会被读成约 1.58 倍，梯度越大压缩越狠。要定量胶片图，必须先把扫描灰度转换成光密度（OD 变换，需要扫描仪的标定曲线或阶梯楔），本工具目前**不做**这一步。

其它前提：

- 同一张膜、同一次曝光内比较。跨曝光、跨膜的绝对值没有可比性，只能比归一化后的比值。
- 条带不能饱和。饱和像素占比 ≥ 5% 的条带会在结果表标橙、标注框转橙——出现就该降低曝光重拍，那条数据不可用。
- 图像不能经过任何非线性后处理（亮度/对比度/伽马/自动色阶）。请用成像仪导出的原始 TIFF。

## 功能

- **现代深色界面**（PySide6）：图像画布支持滚轮缩放、拖拽平移、适应窗口/1:1，右侧控制面板与底部剖面面板可停靠、可折叠
- **16 位 TIFF 原生支持**：加载与定量都在原始位深（8/16/32 位）上进行，显示层单独做 8 位映射，不损失定量精度；命令行走的是同一条通路
- **可调 ROI**：拖拽框选，8 向手柄改大小、整体拖动换位置；橙色泳道分隔线按剖面地形自动放置，可拖动微调（可吸附到剖面谷底）、双击添加、右键删除，也能用方向键 1 px 微调
- **双向同步剖面面板**（pyqtgraph）：ROI 列强度剖面与画布实时联动，分隔线在画布和剖面图里都能拖；定量后可逐泳道查看剖面、基线与积分区间
- **摆正图片两条路**：**标尺对齐**沿条带方向拖一条线一键旋正；**自动测倾角**在 ROI 内自动量一个建议角度（精度 0.02° 量级）并画出参考线——它给建议，不自动旋转，因为它测不出自己什么时候被骗了（方法学第 14 节）
- **ROI 定量**（推荐路径）：ImageJ 式逐泳道基线扣除 + 噪声地板扣除 + 条带横向足迹收紧；另有整图自动检测 + 补画条带兜底
- **每道条带数**：上下叠着的双条带自动判据切不开时，直接告诉软件"每道 2 条"强制切分，与「期望泳道数」对称
- **ROI 质量自检**：每次定量都自动查一遍 ROI 画得对不对，结论写在画布上方的诊断条里，并在画布上直接标出该往哪挪（方法学第 12 节）
- **结果表格**：逐条带位置、平均灰度、背景、积分灰度、饱和占比、信噪比；低于检出限（S/N < 3）的条带压暗标出，选中行高亮对应条带，可删除误检
- **归一化与 fold change**：内参（Loading Control）与目标蛋白**按泳道号**配对；双条带可按位置选取上/下那一条；背景口径随数字走，跨口径直接拒绝配对；历史可导出/导入 CSV 复用
- **发表级导出**：从原始数据出发、16 位无损干净版 + 8 位标注版分层导出，写入 dpi 元数据，并附一份记录全部处理的旁注说明文件（方法学第 15 节）
- **异步与可撤销**：加载、旋转、剖面、定量在后台线程进行，界面不卡；删除、清 ROI、旋转、切换定量路径都可 Ctrl+Z 撤销、Ctrl+Y 重做

## 方法学（数字是怎么来的）

审稿人问到定量口径时，照这一节回答。阈值常量写在 `wb_analyzer/quant.py`、`wb_analyzer/roi.py`、`wb_analyzer/roi_check.py`、`wb_analyzer/tilt.py` 的顶部。

### 1. 位深与白电平

定量在 `BlotImage.raw`（float32，原生取值范围）上进行，8 位显示层只用于预览和粗检测。

`white_level` 是**传感器满量程**，从数据推断而不是取容器上限（`imageio._infer_white_level`）：uint8 → 255；uint16 → 吸附到 255 / 1023 / 4095 / 16383 / 65535 中能装下实际峰值的最小一档。很多成像仪把 10/12/14 位读数写进 16 位 TIFF，若按 65535 算，饱和检测会对一条已经削顶的条带报 0%，极性判别也会跟着错。TIFF 头里的 `SMaxSampleValue`（tag 341）若存在则优先采用，但绝不会小于实际最大值（防止坏标签把真实数据裁掉）。

### 2. 条带极性（深带 / 浅带）

`quant.resolve_dark_bands_native`：条带只会落在强度分布的某一侧尾巴上，所以比较 `median − P0.5` 与 `P99.5 − median`，哪一侧长出 1.5 倍就判哪一侧。这个判据与绝对量程无关。只有两侧尾长相当（没有对比度的空白帧）才退回看边框中位调。也可以在界面上手动指定。

### 3. 条带足迹收紧（tight，默认开启）

泳道条 = 相邻分隔线之间的整条竖带，但条带本身通常只占其中一部分，两侧空白会稀释积分。所以先定位条带的实际横向足迹（`_tight_band_span`）：

1. 在整条泳道的全宽纵向剖面上先分一次条带，得到条带所在的 y 区间；
2. **只在这些条带行**（每段上下各留半个段高的余量）上求列平均剖面——ROI 画得比条带高很多时，空白行会把对比度稀释掉，弱带因此被误判为"不可靠"；
3. **背景电平实测，不靠"泳道里总有空白列"这个假设**（`_strip_background`）：拿条带段**之外的行**的中位数当背景，与列剖面自己的 5 百分位取更低者作为 floor。原先只用 5 百分位，隐含假设"泳道至少 5% 的列是空白"；条带把泳道占满时这个假设直接不成立，5 百分位落到条带自己的平台上，相对切点就从一个高于弱带的电平起算，整条弱带被判在阈值以下切掉——真实样图上这就是一条 250 px 宽的泳道只收到右边 86 px、积分少掉 48% 的原因，而且 ROI 左边缘挪 3 px 就能在"正确"和"漏一条带"之间跳变。条带段之外的行对**每一列**都是背景，与条带横向占了多宽无关，所以这个估计不会随泳道被占满而失效；
4. 以最强列为锚向两侧扩展，直到信号跌破 `floor + 8% × 峰高`（`TIGHT_EDGE_FRAC = 0.08`）；
5. 峰高不显著（≤ 4σ，σ 由列剖面残差的 MAD 估计）就判为找不到可靠条带，**退回整条泳道全宽**；宽度不足 5 px 时向两侧补齐（`TIGHT_MIN_WIDTH`）；条带行已覆盖 ROI 高度 70% 以上（`TIGHT_ROW_COVERAGE`）说明没有空白可排除，列剖面仍用全部行。

关掉 tight（`quantify_lanes(..., tight=False)`）就是老的整条泳道全宽积分。

### 4. 基线扣除：rubber band 下凸包

足迹内逐行求和得到纵向剖面 `profile`，默认基线是 **rubber band**（`quant.rubber_band_baseline`）——想象一条橡皮筋从下方绷紧贴住剖面曲线，也就是剖面的**下凸包**：先做半径 n/100 的滑动平均，在候选点上求下凸包顶点，再线性插值成整条基线。

凸包只需要一个坏点就能把整条弦拽到真实背景以下，所以候选点里先剔除"离群下陷"：用宽度 `min(max(3, n/20), 31)` 的滑动中值给出邻域水平，样本比邻域低出 `max(6σ, 5% × 条带幅度)` 就判为离群（σ = 相邻差分的 MAD，`1.4826 × median(|Δ|) / √2`），并把它前后各 radius 个样本一并排除。实测中一道 3 像素划痕能让邻近条带的积分翻三倍，这一步专治这个；剖面干净时结果与朴素橡皮筋逐位相同。

另有 `valley`（谷–谷折线，局部极小值连线，同样排除离群点）和 `none`（不扣背景）两种模式。

扣除后得到**残差** `residual = profile − baseline`。画在剖面图上、以及用来分段的是它的截断版 `corrected = max(residual, 0)`；但**积分用的是未截断的 `residual`**，原因见下一节。

### 5. 噪声地板扣除

修复前，空白泳道也能积出正值，而且积得比框还大：n=400、σ=10 的纯噪声剖面积出 3610 ≈ 0.9·n·σ，**恒为正**。两个原因叠加：

1. 橡皮筋是**下**包络，本来就压在背景均值之下（剖面越长，凸包能够到的低点越低），空白行的残差平均是个正数 `d`；
2. `max(…, 0)` 把负向涨落全部截掉、只留正向，又额外贴上约 0.6σ。

误差因此正比于**参与积分的样本数**，与真实信号量无关——同一条带，用户把 ROI 拉高一点数值就变大。

两个原因分别处理：

- **截断偏置直接不产生**。积分对 `residual` 求和，不对 `corrected` 求和。空白处的正负涨落自己抵消，不需要事后估计再减掉。条带内部信号远离 0，截不截本来也一样，所以对真条带没有影响。
- **基线偏置 `noise_floor` 实测后扣除**（`quant._lane_noise`）：
  - **空白行**＝所有条带段之外的行，每段上下再各留半个段高的缓冲（段是在 4% 峰高处切的，紧邻的行还带着条带的纵向拖尾）。缓冲不会为了凑样本而缩小：ROI 紧贴条带时空白行不足 12 个（`MIN_NOISE_SAMPLES`），此时地板取 0——宁可不减，也不拿条带自己的拖尾当噪声减（实测那样会啃掉强带 5%）；
  - **`noise_floor`** ＝空白行上 **`residual`（未截断）** 的均值，也就是上面的 `d`。**注意不是 `corrected` 的均值**：后者含着截断贴上去的那 0.6σ，而条带内部并没有被截断过，拿它去减条带会多减两三倍；
  - 上限为 `3 × noise_sigma`（`FLOOR_SIGMA_CAP`），且钳到非负。这既挡住"分段漏掉的拖尾/拖影被当成噪声"，也让无噪声图恰好得 0；
  - **噪声尺度 `noise_sigma`** ＝各段连续空白区内**相邻差分的 MAD**（`1.4826 × median(|Δ|) / √2`）。用差分而不是整体 MAD，是为了不受剖面自身形状影响，也不会在近乎恒定的空白泳道上塌成 0。

于是每个积分都是「窗口内 `residual` 求和 − 样本数 × `noise_floor`」，结果再截到 ≥ 0（灰度积分为负没有物理意义，真正为零的条带由检出限标记来说明）。**噪声为 0 的图（合成图、无噪声渲染）地板恰好为 0，数值与修复前逐位相同。**

分段阈值也跟着变成噪声感知的（`SEGMENT_MIN_SNR = 4`）：空白水平之上不足 4σ 的"峰"不再被切成条带，否则一条纯噪声泳道会被切出一堆假条带，还会污染上面的空白行估计。

实测（合成弱带 深 300 / 噪声 60，8 个噪声实现取平均，真值比 0.0075）：

| ROI 高度 | 60 | 200 | 500 | 三档波动 |
| --- | --- | --- | --- | --- |
| 修复前 | 0.00817 | 0.01022 | 0.01329 | **+62.6%** |
| 修复后 | 0.00758 | 0.00729 | 0.00746 | **+3.9%** |

纯噪声泳道（400 行）：积分 131,193 → **0**，并被标为低于检出限。

环形中值那条路径（自动检测 / 无 ROI 补画，见第 9 节）有同一类截断偏置，但更简单：背景取的是环的**中值**，正好落在噪声中心，所以截断留下的残渣就是教科书上的 `σ/√(2π) ≈ 0.399σ`，按框内像素数扣除，σ 取环上像素的 MAD。

> **仍未解决：橡皮筋的两个端点就是"背景在哪里"的全部依据。** 凸包只能锚在 ROI 的上下两端，而且只能是**凸**的，跟不了缓慢弯曲的背景。所以真正决定误差的**不是 ROI 有多高，而是上下边有没有落在与条带同一片平整背景上**——这是一个**台阶**，不是随高度连续变差的漂移。
>
> 真实化学发光图（10 泳道、每道一对双带）实测：这张膜是剪下来的窄条，只有 y 336–426 这 90 行有膜，框外是相机暗电平（读数 1.7）。
>
> - **不越过时，高度几乎不影响结果。** 顶边 338–344、底边 406–426 之间任取（高度 62–88，2 倍上下），最大泳道误差始终 ≤ 3.6%。
> - **一越过，弦就直接掉到膜外的暗电平上**，整块膜的本底连同拖尾被当成蛋白积进去：**最强泳道的总积分虚涨 60%，相对定量最差错 38%**。
>
> 这与上面的截断偏置是两回事（噪声地板只改动 ≤1%），要根治得换成"每段两侧就近取局部背景"的基线模型。**在那之前**：ROI 的上下边一定要留在膜上（怎么画见第 11 节，定量后软件会自检一遍，见第 12 节），再对同一批要相互比较的图保持同一个高度。

### 6. 条带分段与积分

`quant.segment_bands` 在 `corrected` 上（先做 n/120 平滑）：

- 高于 `4% × 该泳道峰高`（`min_height_frac = 0.04`）且长度 ≥ 3 px 的连续段为候选条带；
- 段内相邻两峰之间的谷，满足下面**任意一条**就切开；
- 每段边缘再收紧到信号跌破 `2% × 段内峰高`（`SEGMENT_EDGE_FRAC = 0.02`）。

切分判据是「几何 **或** 统计」的并联：

| 判据 | 条件 | 管的事 |
| --- | --- | --- |
| 几何 | 谷底 ≤ 较小峰的 70%（`valley_drop = 0.30`） | 分得开的两条带 |
| 统计 | 谷底比较小峰低 ≥ 3σ（`SEGMENT_SPLIT_SIGMA = 3.0`）**且** ≤ 较小峰的 98%（`SEGMENT_SPLIT_MAX_RATIO = 0.98`） | 压在瑞利极限上的重叠双带 |

**为什么光有几何判据不够。** 30% 的谷深要求的分辨率比瑞利判据还高，重叠双带在几何上根本切不开。真实样图（10 个泳道，每道一对双带，实测单带 FWHM 8.5–11.3 px、中心间距 11–14 px，`d/FWHM = 1.02–1.42`）上：两个峰**每道都找到了**，第二峰高出分段阈值 6.9–18.3 倍、高出空白水平 39.7–133.3σ，唯一卡住的就是谷比——8 个泳道停在 0.81–0.96，够不到 0.70，于是 20 条带只检出 12 条。

**为什么不能只把 `valley_drop` 调小。** 要把这批双带全部捞到得放宽到 ≤ 0.036，合成弱带的假分裂率随之从 0.2% 涨到 4.8%（更弱的带 1.7% → 20.7%），放宽 25 倍以上。统计判据换了个维度：谷深不跟峰高比，跟**噪声**比。同一批泳道的谷深实测 4.6σ–23.7σ，`k = 3` 让最难的一道仍有 53% 余量（`k = 4` 只剩 15%，`k = 6` 重新漏掉 2 条）；98% 的相对上限则挡住"统计上显著、物理上没意义"的那一档——强带顶上 1.6% 的起伏能到 26σ，但它不是两条带。实测这条判据把该图从 12 条修正到 20 条、无过分裂，而弱带 / 平顶带 / 空白泳道的假分裂率与修复前**逐格相同**。

统计判据要求 `noise_sigma > 0`。收紧条带足迹那条路径（`_vertical_segments`）按默认的 `noise_sigma = 0` 调用，此时 σ 为 0，不设这道门任何浅谷都会被判为"无穷显著"。

**积分灰度 `integrated_density` = 该段内 `residual` 的逐像素求和，再减去 `段长 × noise_floor`**（不除面积、不除宽度，单位是"灰度×像素"）。整条泳道找不到任何峰时，退回"整条泳道一条记录"——扣完地板后这条记录约等于 0，并会被标为低于检出限。

#### 「每道条带数」（`expected_bands`）：用户直接说每道几条

界面在「调整」页，与「期望泳道数」严格对称（一个管横向切几条泳道，一个管纵向切几条带，`0 = 自动`）。给了 N 就**绕过上面两条判据**，改成"在段内按谷切到 N 段为止"。行为边界要清楚：

- **切哪些谷**：按谷相对较小峰的**下探深度**（`(较小峰 − 谷底) ÷ 较小峰`）排序，从最深的开始切。用相对深度而不是绝对深度，一条浅凹陷挨着强带才不会盖过弱带旁边的真分裂。
- **只补到 N，不拆散已经分开的段**：需要切的刀数 = `N − 当前连续段数`。一条泳道已经被**空白**分成 N 段或更多时刀数 ≤ 0，一刀不切，那些段原样保留——`expected_bands` 没有能力把隔着空白的两条带并回一条。
- **同一个连续段内，它是双向的**：一段连续信号里有 3 个峰、你填 2，就只切 1 刀、得到 2 条带（不是 3 条）。所以"只加刀不合并"这句话只对**空白分开的段**成立，段内的峰数是这个参数直接定的。
- **谷不够时饱和**：可切的谷少于需要的刀数，就有几个切几个，**不报错也不硬切**。切不够的泳道会在画布上方的诊断条里被点名（"已要求每道 N 条带，但泳道 x 没切够"）。
- **不影响足迹定位**：足迹只关心哪些行有信号，切不切开是同一批行。
- 实测在 ROI 本来就画对、自动分段已经给出正确条带数的那批图上，**填不填这个数结果逐位相同**。

膜上的双带贴得比自动判据能分辨的还紧时，这是唯一可靠的兜底——但它**不能替代把 ROI 画对**，见第 12 节。

> **重叠双带的分配比例不可尽信。** 在谷底切一刀不是解卷积：两条带在谷两侧仍然互相贡献着自己的侧翼，强带留得更多。合成图上注入 2.0 的真实比例，切完量出来约 2.3（偏高约 15%）。**分段解决的是"这里有几条带"，不是"各占多少"**——重叠双带之间做定量比较时请留意这一点。

### 7. 饱和判定

`imageio.saturation_fraction`，margin = 0.5%：深带图统计 `像素 ≤ white_level × 0.005` 的占比，浅带图统计 `像素 ≥ white_level × 0.995` 的占比。单条带占比 ≥ 5% 即判为饱和，界面标橙并计数。**饱和条带的积分值一律偏低且不可修**，应重拍。

### 8. 归一化公式

1. 每个蛋白按**泳道号**聚合成一个值。一个泳道里有多条带（双条带）时，这个值是什么由该蛋白自己的**条带策略**决定，见下面的小节。
2. `normalized(lane) = target(lane) ÷ loading_control(lane)`，**按泳道号配对**，不是按列表下标。只在一侧出现的泳道照样成行，值留空并注明原因——绝不静默地把它后面所有泳道错位到邻居身上。
3. `fold_change(lane) = normalized(lane) ÷ normalized(对照泳道)`，对照泳道恒为 1.0，可在界面上指定。
4. 内参强度为 0 的泳道 `normalized` 留空（不作分母）。
5. 目标或内参任一侧低于检出限的泳道照常算出比值，但会在警告栏点名、在结果行注明"低于检出限"——两个测不出来的数相除得到的是算术，不是测量。
6. **配对双方必须是同一套背景口径**（下一节）。

#### 双条带：一个泳道里有两条时取哪一条

| 策略 | CSV 里的 `band_pick` | 取哪些条带 |
| --- | --- | --- |
| 合并全部（默认） | `all` | 该泳道所有条带 `integrated_density` 之和 |
| 只取上面那条 | `top` | 图像坐标 y 最小的那一条 |
| 只取下面那条 | `bottom` | y 最大的那一条 |

- **按蛋白设置**，在「归一化」页历史表的"条带"列双击修改。内参取下面那条、目标取上面那条是允许的组合。
- **按位置取，不按强弱。** 双条带通常是同一蛋白的不同修饰形式，分子量位置比亮度稳定得多。
- **一条泳道只跑出一条带时，选上选下都用这一条**（"只有一条"不等于"不要这条"）。界面会点名这些泳道并说明策略在它们身上没生效——否则用户会以为自己选的策略起了作用，而实际上那几道根本没被切成两条。
- **三条及以上时，"上面那条"就是最靠上的那一条**，没有"上面两条求和"这种中间态。
- **未被采用的条带仍然保留、仍然显示**：结果表里标"未采用"、积分灰度划删除线，画布上画成虚线框。这和"删除"是两回事——删除才会让它彻底消失。
- **改策略是重新聚合，不需要重新定量**，也不需要图还开着（逐条带明细存在记录里）。唯一的例外是从 CSV 导入的记录：那里只有聚合值，改策略会明确报错要求重新定量。
- 背景与平均灰度取**被采用条带**的均值；某泳道的采用条带**全部**低于检出限时，该泳道才算低于检出限。删掉误检条带后聚合值随之变小；整条泳道被删空则该泳道号留下空档。

### 9. 两套背景口径不可混用

- **ROI 定量**（推荐）：上面第 3–6 步，橡皮筋基线 + 噪声地板。CSV 里记作 `roi_baseline`。
- **整图自动检测**与**无 ROI 时补画的条带**：环形中值局部背景（`quant.measure_box_native`）——取框外一圈（左右各 ¼ 框宽、上下各 ½ 框高）的中值作背景，积分 = `Σ max(背景 − 像素, 0) − 0.399 σ_ring × 框内像素数`。CSV 里记作 `local_background`。

两者数值口径不同，**不要放进同一次比较**。有 ROI 时补画的条带会自动走 ROI 那套口径；万一退回局部背景口径，状态栏会明确提示。界面上两条路径互斥：切到另一条时上一条留下的框 / ROI 会被清掉（可 Ctrl+Z 撤回）。

**口径跟着数字走。** 每条 `QuantEntry`（归一化历史里的一行）都带着自己的 `origin`，导出的 CSV 也有这一列，历史表里有"口径"列可看。归一化时：

| 两侧口径 | 处理 |
| --- | --- |
| 相同 | 正常计算 |
| **都已知但不同** | **直接拒绝配对**：`normalized` 与 `fold_change` 留空、`note` 写"背景口径不一致"，警告栏点名，界面上整行标红并在最左侧打 ⛔。**两侧的原始测量值照常显示**——它们各自都是对的，错的只是它们的商 |
| 一侧已知、一侧未知 | 允许配对，但警告栏说明无法确认两者是否同源，比值仅供参考 |

拒绝而不是警告是有意的：警告用户可以点掉，而跨口径的比值错了一个未知倍数，**没有哪种读法是对的**。"未知"（`unknown`）是真实的第三种状态，不是默认猜测——旧版 CSV 导入、以及任何没有声明口径的调用方都落在这里；如果把它默认成某一套，就正好制造了这个字段要防的错误。一个文件里 `origin` 列前后不一致时，整个蛋白按"未知"处理并给出警告。

### 10. 检出限（LOD）与信噪比

积分窗口越宽，攒进来的随机噪声越多：逐样本噪声按平方根累加。所以每个条带都有自己的门槛：

```
detection_limit = 3 × noise_sigma × √(积分窗口的样本数)
snr             = integrated_density ÷ (noise_sigma × √(样本数))
```

`snr < 3`（等价于 `integrated_density < detection_limit`）的条带被标为**低于检出限**：它的积分与一条空白泳道在统计上无法区分。样本数在 ROI 路径上是条带段的**行数**，在环形中值路径上是框内**像素数**；两条路径的 σ 分别取空白行差分 MAD 与环上像素 MAD。

**噪声估不出来时**（合成的无噪声图、或条带塞满 ROI 没有空白可用），`detection_limit` 记为 `0`，表示"未评估"，此时不会给任何条带打标——工具不会假装做过它没做的判断。

标记会同时出现在四处：

| 位置 | 表现 |
| --- | --- |
| 结果表 | `S/N` 列；低于检出限的整行压暗，悬停说明原因，表头计数里单列"N 个低于检出限 ⚠" |
| 画布 | 条带框改用钢蓝色（正常红、饱和橙），悬停显示 S/N 与检出限 |
| CSV 导出 | `detection_limit` / `snr` / `below_detection` 三列（`below_detection` 为 0/1）；标注图里这些框也是钢蓝色 |
| 归一化 | 加入历史时状态栏点名相关泳道；归一化结果行注明"低于检出限"，警告栏说明该比值不可信 |

**怎么解读**：低于检出限**不等于**"这个泳道没有蛋白"，只等于"这次曝光下测不出来"。正确的做法是延长曝光或上样后重拍，而不是引用那个数字。也不要把它当成 0 去算倍数变化——分母是它的时候尤其危险。

**反过来也不成立：`below_detection = False` 不等于"这道有蛋白"。** 它是**噪声限**，量的是"这个积分比随机涨落大多少"，它不知道积分里混进来的是不是膜背景。ROI 画错时一条肉眼全空的泳道照样能拿到 S/N 8–37 的"条带"，软件不会告诉你那是空的。这一条见「已知限制」。

> **旧版本数据要重新解读。** 加入噪声地板扣除之前，弱条带的数值里混着一份正比于 ROI 高度的背景残渣，**偏高**。实测下降幅度（弱/强比值，ROI 拉得越高降得越多）：ROI 高 500 降 **44%**（0.01329 → 0.00746，真值 0.0075），ROI 高 200 降 **29%**，ROI 高 60 降 **7%**；纯噪声区域从六位数降到 0。强条带几乎不动：**−0.05% ~ −0.07%**；ROI 紧贴条带（高 60、空白不足以估计地板）时为 −2.6%，这来自分段口径变噪声感知与积分不再截断，不是扣地板。真 16 位化学发光图 + 强条带这条日常路径，逐泳道变化 **0 ~ −0.3%**。用旧版本得到的弱带数字请重新定量，不要与新数字混用。

### 11. ROI 该怎么画（照着做）

橡皮筋基线是**在 ROI 内部**绷起来的，它只能锚在 ROI 的上下两端。所以 ROI 的上下边落在哪里，就等于在告诉工具"这里是背景"。落错了地方，条带底下那根弦会一路沉到那个错误的电平，中间的一切——膜的本底辉光、拖尾、隔壁那行条带——统统被当成信号积进去。

一次覆盖 8 张真实膜、1377 次 ROI 扫描、3344 次敏感度测量的调查给出下面几条。**按优先级排列，冲突时前面的赢。**

#### 规则 1（硬规则）：ROI 的上下边必须落在膜上

和条带处在同一片背景里，**不能越到膜外的扫描仪暗底**。操作上：上下边分别从膜的上下边缘**向内收至少 8% 的膜高**。

实测的代价（"敏感度"＝把 ROI 的边挪 1 px，泳道读数变化百分之几；越小越稳）：

| ROI 上下边的位置 | 中位敏感度 |
| --- | --- |
| **向内收 12% 膜高** | **0.079 %/px** |
| 与膜边齐平 | 0.65 %/px |
| 越过膜边 | 0.88 %/px |

差了将近一个数量级：画在膜里面时，边挪十几个像素也就动千分之几；一旦齐边或越界，每挪 1 px 读数就动近 1%，也就是说这时候"ROI 画在哪"本身成了误差的主要来源。第 5 节那张膜上，越过膜边的具体后果是最强泳道虚涨 60%、相对定量最差错 38%，而条带数看上去完全正常。

#### 规则 2：在规则 1 允许的范围内，上下各留半个条带高度的空白

留白是给噪声地板和检出限用的：空白行不足 12 个（`MIN_NOISE_SAMPLES`）时 `noise_floor` 直接取 0、`noise_sigma` 退回整条剖面的差分估计，检出限会虚高几十倍（实测：高 80 的 ROI 检出限 72，压到高 40 就成了 3047）。

**这一条经常和规则 1 冲突，冲突时以规则 1 为准。** 这批膜的垂直高度实测只有 95–152 px，与条带自身的行跨度基本同量级——"高度取条带跨度的 2 倍"在这种窄条膜上根本放不下，硬凑就得越过膜边，那是拿 10%~50% 的误差去换检出限的准确度，不划算。**膜够高时**（条带上下都有大片干净膜），2 倍是个好目标：8 位单条带的 `pad4_001(1)_signal.tif`（8 泳道、条带行跨度 53 px）上，高度取 1.8–2.4 倍时最大泳道误差 3.6%~4.8%，低于 1.2 倍涨到 8.6%~17%，高于 5 倍涨到 10% 以上。

#### 规则 3：分隔线放在两条带之间的空隙里，任意位置即可

**不必刻意放正中。** 实测把分隔线在空隙内任意移动（n=178，含最宽 50 px 的空隙）：泳道积分误差 ≤ 1.9%，相邻泳道比值误差 ≤ 2.7%。何况日常空隙的中位宽度只有 4 px、p75 只有 5 px，本来也挪不了多少。

真正要紧的是**别让分隔线切进条带**——那会把一条条带的左右两半算成两个泳道的信号，两个泳道的数都作废。软件会替你查这一条（第 12 节的判据 3），被点名的分隔线在画布上会变红加粗。

#### 规则 4：同一批要相互比较的图，用同一个高度

剩下的那点系统偏差在同高度的图之间会大部分抵消；高度不一样时它不会。

#### 规则 5：自检报 error 时，先改 ROI，再看数字

自检的报警与分隔线敏感度的交叉表（3344 次测量）：

| 自检结论 | 分隔线敏感度中位 | 最大 |
| --- | --- | --- |
| 通过 | 0.245 %/px | 2.84 %/px |
| 报 error | 0.787 %/px | 15.64 %/px |

而且**最差的 12 次测量全部被自检报了 error，零漏报**。所以顺序是固定的：先把自检报的 error 改完，再去读表里的数字；在那之前挪分隔线、调参数都是在错误的地基上做微调。

#### 额外提醒：特别宽的空隙 + 看不见条带的那一道

某条空隙特别宽（> 40 px）、而相邻某个泳道肉眼看不到条带时，那一道的积分**可能整个是膜背景**。判据很简单：**把那条分隔线在空隙里挪 20 px，如果该道读数变化超过一倍，它就不是条带。** 真条带的读数不会因为分隔线在空隙里挪一点就翻倍（见规则 3 的 ≤1.9%）。

实测一张动态范围很大的膜（最弱带与最强带相差约 4 倍、强带周围一圈弥散辉光，其中一道肉眼看不到条带）上，ROI 画错会把这条空泳道虚增约 **25 倍**——它读到了参考泳道的 29.8%，看上去像一条弱带；把 ROI 画对之后是 1.22%。这条泳道在两种画法下都是 `below_detection = False`，软件不会替你识破它，见「已知限制」。

### 12. ROI 质量自检（软件替你查的那几条）

`wb_analyzer.roi_check.check_roi_quality(lanes, expected_bands=…)` 吃一次 ROI 定量的结果，吐出结构化诊断：有没有问题、是哪一类、涉及哪些泳道 / 条带、该往哪个方向挪多少像素。界面每次 ROI 定量都会自动跑一遍，结论显示在画布上方那条诊断条里。

**它只诊断、不拒绝**，一个数字都不会改——膜上就只有那么窄一条时，"画错"也可能是唯一能画的画法。确有理由那样画就点"我知道了"收起提示；ROI、每道条带数或问题本身一变，提示会自己回来。

三条判据：

1. **条带数 = 泳道数 × 每道条带数。** 多出来的那些，就是基线沉下去之后被误当成条带的背景。"每道条带数"你不填就取各泳道条带数的**众数**（并列时押更少的那个），点名的是与众数对不上的那几道。各泳道条带数本身就很散时，它会额外说一句"连每道几条都难说"——那种散法本身就说明上下边多半没落在同一片平整背景上。
2. **每个条带框离 ROI 上下边至少半个条带高度。** 贴边说明这一侧根本没有背景可锚。"条带高度"取**实际检出条带高度的中位数**，所以换膜、换放大倍率、换分辨率都不用调参数；留白不足半个条带高度报"警告"，不足四分之一报"严重"（那一档往往已经把条带切掉一截）。上下边**分开报**，措辞也分开（形如"把 ROI 上边往上挪至少 5 px"）；画布上会在那条边内侧画出要求的留白（斜纹带），把边拖到斜纹空出来即可。没检出条带的空泳道单独列一条，不参与前两条的比对。
3. **条带的横向足迹没有被泳道分界切断。** 前两条只看纵向，从来不看足迹的左右边界，所以"分隔线从条带中间穿过去"对它们完全隐形：条带数照样对、上下留白照样够、表里全是正数，只是每条条带的信号被劈成两半算进了两个泳道。判据是几何的三合一——足迹**窄**于半个泳道间距、**一侧顶死**在分界上（与邻居的空隙 ≤ 0）、**另一侧还空着**（这是"它确实收紧过"的证明）。三条缺一不可：只看"窄"准确率 0.47（基础率 0.52），只看"顶死"准确率 0.43（基础率 0.37），三条合起来实测准确率 0.83（1584 个真实 ROI、11087 条泳道）。一条分隔线两侧的足迹都紧贴着它、且至少一侧偏窄时，还会单独报一条"分隔线切在条带里"（准确率 0.886），把那条线在画布上标红加粗——它一次点掉两个泳道，要修的是那条线而不是某个泳道。

纵向那两条（判据 1、2）在真实样图的 1044 个 ROI 上**同时通过时最大泳道误差从未超过 5%，零漏报**；代价是有意偏保守，一部分其实还行的 ROI 也会被拦下（把判据 2 的"半个条带高度"放宽能让误报少四成，但 5%~6% 那一档的漏报翻倍，所以没有那么改）。横向那一条（判据 3）的覆盖情况差得多，见「已知限制」第 1 条。

**填了「每道条带数」时多一条对照。** 强制切分会让判据 1 变成同义反复——段是按这个数切出来的。所以自检会**把自动分段重新跑一遍**（同一批剖面，只是不强制切分）去对照：自动说 30 条、你说每道 2 条，它就直接报"强制切分掩盖了分段异常"。填对了也照样会留一句提示，说明这个条带数是切出来的、不能当作 ROI 画对的证据。

> **`expected_bands` 不能替代把 ROI 画对。** 它只决定"切几刀"，不改变基线。ROI 画高了它反而更危险：一个明显过高的框自动分段给出 30 条带（一眼看出不对），填上"每道 2 条"之后给出整整 20 条带、看上去完全正常，而最大泳道误差是 **34%**——判据 1 就此失效，只剩判据 2、3 挡着。它真正的用武之地是 ROI 已经画对、但双带贴得太紧、自动判据切不开。

**它查不出什么**（这几件仍然要自己看一眼图）：

- **ROI 边压在膜边上、而条带离得还远。** 判据 2 量的是条带框到 ROI 边的距离，不看 ROI 边**下面**是不是平整背景。实测底边正好落在膜下沿时两条判据都通过，最大泳道误差却到 **9.6%**。
- **每个泳道都多切了一段。** 判据 1 靠的是泳道之间对不上；ROI 系统性地把相邻那一行条带整个框了进来时，众数自己跟着变成 3，它就没话说了。
- **足迹整条退回泳道全宽的那一类横向缺陷**（约 85%，见「已知限制」）。
- **膜本身不平、曝光不匀、背景带梯度**：判据只看几何，不看背景电平。
- **重叠双带的分配比例**（第 6 节末）和**饱和**（第 7 节）是另外的问题，不在自检范围内。

### 13. 泳道分隔线是怎么放的

`roi.separators_from_profile` 直接读 ROI 列剖面的地形，而不是等分：找局部极值 → 持久性剪枝去掉空白区噪声峰 → 算每个谷相对两侧峰顶的下探深度 → 量出"一条泳道该有多少条带足迹" → **划掉落在同一条条带两个鼓包之间的候选谷** → 在条带区内用动态规划挑一组分隔线（目标 = 谷质量 + 足迹宽度偏离先验）→ 抹掉空白泳道 → 落在大片空白里的分隔线挪到空白正中。

两个设计要点：

- **约束的是"泳道里装了多少条带足迹"，不是泳道的几何宽度。** 泳道旁边空多少无所谓，装了几条条带才有所谓——中间整段空白因此天然免罚，而两条泳道没切开时足迹是 2 个单位、代价超过 11，压得过任何一条浅谷的质量代价。真实样图里相对深度只有 0.08 的那条真分隔线就是这样切下来的。
- **条带数按"条带有多宽"数，不按幅度。** 谷深只圈出一个两头都可靠的区间（深过 0.40 一定是两条带，浅过 0.05 一定不是），区间内由归并半径（0.57 × 条带宽）定夺。原先按绝对幅度数，ROI 往上多框十几行空白就会让两个浅肩峰消失，条带数从 8 掉到 6、单位宽度虚高 34%，跟着丢掉 3 条分隔线。

「期望泳道数」填了就强制切出这么多条（位置仍由剖面决定）；地形证据不足时回退到旧的等宽网格 + 谷位吸附。这套逻辑在几张真实膜上仍会失手，见「已知限制」。

### 14. 自动测倾角

「调整」页的**自动测倾角**按钮（`wb_analyzer.tilt.estimate_tilt`）。

**原理**：把 ROI 按不同角度做垂直**错切**，取"每行的列平均"（行投影），真正水平的那个角度上行投影的边缘最陡——因为同一条带的所有像素都落进了同一行。于是在一组候选角度上取行投影平方梯度和 `Σ(Δp)²` 的极大值点。±10° 范围内先按 0.5° 粗扫、再按 0.05° 细扫，最后做抛物线插值。用错切而不是真旋转，是因为错切不改外形、不用扩画布，也就没有旋转留下的空角和假边缘。

**精度**：中位误差 **0.023°**、p90 **0.125°**，单次约 **14 ms**。横向对比过 Hough（RMS 1.76°）、结构张量（2.05°）、FFT 主方向（5.02°），本方法 RMS 0.107°，差一个数量级。

**它无法自判失败——这一点决定了它该怎么用。** 调查在 468 个 ROI 样本上试过 5 种自检判据（峰突出度、方差判据一致性、行列一致性、三分块一致性、是否顶到搜索上限），好样本与坏样本的分布几乎完全重叠：真正要命的失败都是**自洽**的，所有子判据被同一条强直线一起骗到，自然互相同意。最好的标定规则覆盖率只有 33%，假自信率仍有 3.9%。所以本模块不做任何置信度评分。

挡不住的两种失败：

- **贯穿全宽的淡划痕**（20% 对比度）：算法会锁到划痕上，报出一个几度的错误角度，`reason_code` 照样是 `ok`（实测 p90 误差 7.43°）。
- **ROI 里框进了膜边、胶带一类硬直线**：它报的是那条边的角度，不是条带的角度。四边各内缩 4% 只能挡住紧贴边的一点点。

能挡住的只有三条**事先可验证的工程约束**，它们不是算法自省：

1. 没有 ROI —— 拒答（整图上算会锁到扫描边框上）；
2. 裁切宽度 < 250 px —— 拒答（两端高差不够，角度杠杆不足；实测 <200 px 时 median 误差 0.23° / p90 1.34°，≥350 px 是 0.022° / 0.077°）；
3. 极值点顶到 ±10° 边界 —— 拒答，不返回边界值（歪超过 10° 该先用整 90° 旋转摆正）。

另有"选区里看不到条带结构"一档也会拒答。拒答时状态栏说明原因，**此前手动量的标尺值不受影响**。

**所以界面绝不自动旋转。** 测出的角度只写进标尺位、并在画布上按该角度画一条虚线参考线；**用户看着这条线与条带平行了，再点"旋正为水平"**。这一步不是客套——它是这个功能唯一的正确性保障，跳过它就等于接受一个无人复核的角度。ROI 请框在条带上，别贴着膜边。

旋转角输入框保留 2 位小数（0.01°），因为自动测角与标尺量出来的都是这个量级；左边的滑杆是 0.1° 一格的粗调。

### 15. 发表级导出（展示图 + 旁注说明）

`Ctrl+Shift+E`。整条链路从 `blot.raw` 出发，**不经过屏幕预览那张 8 位图**。

**灰度映射是唯一不可逆的一步**，所以它被摆在对话框最上面，而且**两个版本各选各的**——用一个下拉管两版，必然有一版是错的：

| 映射 | 做什么 | 谁用 |
| --- | --- | --- |
| 线性全量程（干净版默认） | 原始值 0 → 黑、传感器满量程 → 白 | 存档、定量凭据；不拉伸、不削波 |
| 自动对比度拉伸（标注版默认） | 第 0.05 / 99.85 百分位拉满 | 给人看；真实膜的数据常挤在量程顶部不到 1% 的区间里，8 位图按线性映射只剩两百来个灰阶，屏幕上看不出条带 |
| 手动黑白点 | 你自己填两个原始灰度值 | 需要跨图统一映射时 |

其余的处理都是无损或不做：

- **干净版与标注版分层导出**：干净版无标注、可保持 16 位单通道；标注版叠加条带框 / 文字标签 / ROI 框 / 泳道分隔线（可逐层勾选），固定 8 位彩色——没有主流写库能出 16 位 RGB，与其悄悄降位深不如明说。标注版文件名自动加 `_annotated` 后缀。
- **只写无损容器**（TIFF / PNG）。TIFF 用 LZW。JPEG 一律拒绝：实测它在真实膜上把灰度改动 6–7 级，与真实的强度差异无法区分。
- **导出时从原图按 Lanczos-4 重新旋正一次**（画布上那张是双线性的，为了拖动流畅）。Lanczos 会在边缘过冲，结果会被钳回源数据的取值范围。
- **写入 dpi 元数据**（TIFF 分辨率标签 / PNG pHYs）。
- **削波占比在输出图上实测**，不是按映射窗口算的：舍入也会把像素压到两端，而且影响大得多——真实 16 位膜上 0.05/99.85 百分位拉伸形式上只排除了 0.15% 的像素，实际却把 **41.8%** 的像素推到了 255。落在同一个极值上的像素之间再也分不出差别，不管它们是怎么到那儿的，所以该报的是这个数。

#### 旁注文件 `*_export_info.txt`（这个功能的核心）

每张导出的图旁边都会写一个同名的 `_export_info.txt`，导出完成后还会弹出来给你看一眼（没人会主动去开一个 txt）。它记录这张图从原始数据到成图的全部处理：

| 段落 | 内容 |
| --- | --- |
| 源数据 | 存储位深、满量程（传感器白电平，非容器上限）、原始尺寸 |
| 几何 | 旋正了多少度 / 什么方向 / 什么插值；裁切区域（原图坐标）；**重采样：无** |
| 灰度映射 | 映射方式、黑点、白点（都是原始灰度值）、自动映射时用的百分位、传递函数（线性，未做伽马/曲线/局部调整）、输出格式与压缩、**纯黑与纯白的削波占比** |
| 打印尺寸 | 写入文件的 dpi 标签；此图印成 X mm 宽时相当于多少 dpi；要 300 dpi 最大能印多宽；要 600 dpi 最大能印多宽 |
| 标注 | 画了哪几层，以及"标注仅覆盖在图像之上，未改动下方任何像素的灰度" |
| **方法学建议写法** | 一段完整的中文句子，把上面这些拼成可以直接抄进论文方法学的表述 |

审稿人问"你对这张图做了什么"时，这个文件就是答案。

#### dpi 不是一个可以调大的设置

**本软件从不插值放大。** 像素数是采集时定死的，dpi 只是"这些像素印多宽"的结果：

```
dpi = 像素宽 ÷ 印刷宽度（英寸）
```

所以对话框里能填的是**打印宽度**，旁边实时显示算出来的 dpi——拉宽度就能看见分辨率掉下去。举例：一条膜裁出来 624 px 宽，

- 印 **52.8 mm** 宽 = 300 dpi（多数期刊的下限）
- 印 **26.4 mm** 宽 = 600 dpi

要更高的分辨率，只能**在成像那一步解决**（更高分辨率扫描 / 更大放大倍率重拍）。任何软件把 624 px 插值成 1248 px 都不会增加一点信息，只会让审稿人拿到一张糊图。

## 已知限制

这一轮调查查出、但当前版本**没有修**的问题。每条都写清：现象、量级、什么情况下会踩、怎么规避。

### 定量与 ROI

**1. ROI 自检看不见约 85% 的横向缺陷。**
判据 3 要求足迹"一侧顶死、另一侧还空着"，因为那是"这条足迹确实收紧过"的证明。但足迹收不动时会**整条退回泳道全宽**，那种足迹**两侧都**贴着邻居（实测 5378 条两侧都贴的足迹里，收紧过的一条也没有），判据于是一声不吭。ROI 粒度的召回率只有 **0.175**。干净 ROI 上的误报率 4.1%；泳道条宽度很不均匀的 ROI **必然**误报，因为"泳道间距"取的是相邻足迹中心距的中位数。

*怎么规避*：自检通过不代表横向没问题，请对着画布看一眼每条分隔线是不是落在空隙里。宽窄不均的膜上收到判据 3 的警告，先看图再决定要不要理。

**2. 重叠双带的分配比例不可尽信。**
谷底切一刀不是解卷积，两条带在谷两侧仍互相贡献侧翼。合成图注入真实比例 2.0，量出约 2.3（**偏高约 15%**）。踩到的场合：拿同一泳道内双带的上/下比值当结论。

*怎么规避*：分段回答"有几条带"，不回答"各占多少"。要比上下两条带，请换能真正分开它们的方法（更长的胶、更小的孔径），或只报"存在两种形式"。

**3. 自动判据在 d/FWHM ≈ 1.0 时召回率只有 2.5%。**
两条带中心间距接近单带半高宽时，几何判据（谷深 30%）和统计判据（3σ）都够不着，自动分段只给一条。

*怎么规避*：用「每道条带数」强制切分。填之前先确认 ROI 画对了（第 12 节）。

**4. 微笑凹陷深过约 50% 时，一条条带会被切成两条泳道。**
弯条带的列剖面上一条带有两个鼓包，中间一个凹陷。实测（合成剖面）相对深度 ≤ 0.50 时分隔线放置完全正常；**≥ 0.57 时每条条带都被从正中劈开**，8 条条带切出 16 条泳道。真实膜上的微笑凹陷实测 0.006~0.208，通常够不到这个门槛。

*怎么规避*：泳道数明显翻倍时，填「期望泳道数」；分隔线位置仍由剖面决定，只是数量被钉住。

**5. 弱到低于最强带 12% 的条带不被计数，那条泳道拿不到分隔线。**
`BAND_LEVEL_FRAC = 0.12` 是"这一列上有条带"的全局电平，从剖面地板起算、占动态范围的比例。实测：弱/强 = 0.15 时 8 条泳道全部切开；**弱/强 ≤ 0.12 时那条泳道的分隔线消失**（7 条变 6 条）。换句话说**同一 ROI 内动态范围超过约 8 倍**，最弱的那道就会被并进邻居。

*怎么规避*：填「期望泳道数」强制切出应有的道数，再手动把分隔线拖到位。

**6. 足迹总量在动态范围大的膜上仍虚高约一倍。**
同一个全局电平（`BAND_LEVEL_FRAC`）之上的列数被当作"条带足迹总量"，强带的两侧裙边整片高过这个电平，于是足迹总量虚高约一倍。它**不再导致分隔线放错**（放置改用相对位置判据之后），但"一条泳道该有多宽"的先验跟着变宽，**会挡掉合法的窄泳道**。

*怎么规避*：窄泳道被吞掉时，同样用「期望泳道数」。

**7. 弱泳道上噪声地板会在 0 与 45–71/行之间翻转，造成 20–30% 的台阶跳变。**
空白行少于 12 个（`MIN_NOISE_SAMPLES`）时 `noise_floor` 直接取 0，够 12 个就按实测值扣。于是 ROI 高度、条带分段结果的一点点变化，就能让同一条弱带的积分在"扣了地板"和"没扣地板"之间跳一档。**这与 ROI 画得对不对无关，画对了也治不了。**

*怎么规避*：同一批要比较的图用同一个 ROI 高度（第 11 节规则 4）；弱带数值出现无法解释的台阶时，检查那几道的空白行是不是正好卡在 12 附近。

**8. 噪声地板在真实扫描图上只扣掉一部分。**
相邻行是相关的，用相邻差分估出的 σ 因此偏小，而 `noise_floor` 被 `3σ` 封顶（`FLOOR_SIGMA_CAP`）。实测一张化学发光膜：空白行比基线高出 14–53 个单位，而 3σ 只有 8–9，所以只扣掉了其中一部分。这是**有意偏向"少扣"**的——多扣会啃掉真信号。

*怎么规避*：这不是日常路径的主项（那张图上占比远小于 ROI 边越界的影响），按第 11 节画好 ROI 即可。

**9. `below_detection` 是噪声限，不是背景系统误差限。**
它只回答"这个积分比随机涨落大多少"，不回答"积分里是不是全是膜背景"。实测一张动态范围很大的膜（最弱带与最强带相差约 4 倍、强带周围一圈弥散辉光）上，即使 ROI 画对，一条实际是空的泳道，其 7 条"带"的 S/N 仍有 **8–37**、`below_detection = False`——**软件不会告诉用户这一道是空的**。

*怎么规避*：用第 11 节最后那条判据（分隔线在空隙里挪 20 px，读数变化超过一倍就不是条带），并且始终对着图确认那道肉眼有没有条带。

**10. `expected_bands` 不能把隔着空白的两条带并回一条。**
刀数 = `N − 当前连续段数`，段数已经 ≥ N 时一刀不切。所以一条已被空白分成 3 段的泳道，填 2 仍然是 3 条。（同一个**连续段**内它是双向的，填 2 会把 3 个峰切成 2 条——见第 6 节。）

*怎么规避*：多切出来的段通常是 ROI 画错的症状，去改 ROI，而不是靠这个参数抹平。

### 分隔线自动放置

**11. 有些膜上自动放置完全不可用，必须手动指定泳道数。**
实测一张 8 泳道的膜（正确应给 7 条分隔线）：ROI 的左右边只要比条带所在的列范围多出 **2 px**，`separators_from_profile` 就返回**空列表**（一条分隔线都不给）；正好贴齐条带列时才给出正确的 7 条。同一张图上按 390 种取景扫描，落在正确条带数上的只有个位数，其余不是给 0~5 条就是在空白区里炸出几十条。

*怎么规避*：**填「期望泳道数」**。填了以后同样这些取景全部稳定给出 7 条分隔线，位置仍由剖面决定。这也是遇到任何"分隔线看着不对"时的第一反应。

### 自动测倾角

**12. 它测不出自己被骗了。**
贯穿全宽的淡划痕（20% 对比度）会让它锁到划痕上（p90 误差 7.43°），ROI 里框进膜边、胶带时它报的是那条边的角度——两种情况下 `reason_code` 都是 `ok`，语气与正确时完全一样。三条拒答约束（没 ROI / 宽度 < 250 px / 顶到 ±10°）都是事先可验证的工程约束，拦不住这两种。

*怎么规避*：**看画布上那条虚线参考线**，确认它与条带平行再旋正。ROI 框在条带上，别贴着膜边或划痕。这一步没有替代品（详见第 14 节）。

### 导出

**13. 标注版只能是 8 位彩色。**
彩色标注需要 RGB，而没有主流写库能产出 16 位 RGB。软件的做法是明确报错而不是悄悄降位深：干净版仍然保持你选的位深。

*怎么规避*：需要 16 位存档就导干净版，标注版另存一份 8 位的。

**14. 旧接口 `export.export_figure` 说不出自己做过什么。**
它从一张已经渲染好的 8 位图裁切导出，没有映射信息、没有旁注文件，传入有损后缀时会静默改写成 `.png`。

*怎么规避*：任何要发表的图都走 `Ctrl+Shift+E` / `export_presentation_figure`。

### 软件内推荐流程

1. **打开图片**，或把图片直接拖进窗口（支持 8/16 位 TIF/TIFF、PNG、JPG、BMP）。
2. **摆正**。图片歪斜时用 **标尺对齐**（`2`）沿条带方向拖一条线，点"旋正为水平/垂直"；微调范围 ±45°，横竖颠倒先用 **编辑 → 旋转 90°**。框好 ROI 后也可以点「调整」页的 **自动测倾角**：它只写角度、画一条虚线参考线，**确认参考线与条带平行后**再点旋正（为什么必须人工确认见方法学第 14 节）。ROI 与分隔线会随旋转自动重映射。
3. **框 ROI**（`1`）。上下边一定要留在膜上、离膜边内收 ≥ 8% 膜高（方法学第 11 节）；分隔线按剖面地形自动划分泳道。分隔线看着不对时，先去「调整」页填**期望泳道数**——那比手工一条条拖有效得多。分隔线在画布或底部剖面图中都能拖动微调；「调整」模式（`4`）下双击添加、右键删除。
4. **看诊断条**。框好 ROI 会**自动定量**（微调分隔线也会自动刷新），也可按 `Ctrl+R` 手动重跑。画布上方那条就是 ROI 自检结论：绿色"自检通过"最常见；橙色"警告"、红色"严重"会给出具体动作（"把 ROI 上边往上挪至少 8 px"这种），点"详情"看全文。被点到的条带框右上角有三角角标，ROI 那条边上会画出要求的留白（斜纹带），被点名的分隔线会变红加粗。**先按它说的改 ROI，再读数字。** 确有理由那样画就点"我知道了"。
5. **补漏与删误检**。漏检用 **补画条带**（`3`）补；误检在结果表或画布上选中后 `Delete` 删除（可撤销，批量删算一步）。每道上下叠着双条带而只切出一条时，把「调整」页的**每道条带数**填成 2。
6. **归一化**。在「归一化」页把内参与目标分别加入历史（选好类型/蛋白名/分组），同组按泳道号自动配对计算 normalized 与 fold change，可设对照泳道。双条带可在历史表"条带"列里选"只取上面那条 / 只取下面那条"——改的是聚合方式，不重新定量。
7. **导出**。`Ctrl+E` 出条带 CSV + 标注图；`Ctrl+Shift+E` 出发表级展示图（先问干净版/标注版、灰度映射、位深、打印宽度，导完弹出旁注内容给你看一眼）。

> 删掉误检条带后，加入历史的强度是**剩余条带**的合计，并且会记下泳道号；
> 整条泳道被删空时该泳道号留空档，归一化里会单独成行并注明"缺该泳道"。


命令行单张自动分析：

```powershell
wb-analyze .\example.tif --output .\results
wb-analyze .\example.tif -o .\results --sensitivity 0.8 --background dark_bands
```

支持 PNG、JPG、JPEG、BMP 和 TIFF。

### 命令行也是原生位深（重要，涉及旧结果）

`wb-analyze` 与图形界面走**同一条原生位深通路**：`cli.main` → `analysis.analyze_image` → `imageio.load_blot` 按原始位深读入 → 在 8 位显示层上做条带**检测**（CLAHE 与 Otsu 只能吃 uint8）→ `quant.remeasure_native` 在未经缩放的 `raw` 平面上**复测**每一个框。CSV 里的每个数字都来自 raw 平面。

> **旧版本 CLI 的结果与新版本不可比，需要重跑。** 旧实现用 `cv2.IMREAD_COLOR` 读图，
> 会先把 16 位曝光压成 256 个灰阶再测量：绝对值差约 257 倍，更要紧的是量化到 256 级
> 之后弱条带的相对强度也会失真，所以**连比值都不能沿用**。凡是用旧版本 CLI 跑过的
> 16 位图，请用当前版本重新分析。8 位输入的旧结果不受影响。

## 参数说明（CLI）

| 参数 | 含义 |
| --- | --- |
| `--sensitivity` | 检测灵敏度。默认 `1.0`；越小越容易检出弱条带，越大越严格（内部钳制到 0.35–2.5） |
| `--kernel-size` | 背景校正形态学核（奇数）。省略则按图片尺寸自动估计 |
| `--background` | `auto` / `dark_bands`（深带浅底）/ `light_bands`（浅带深底） |
| `--output` / `-o` | 结果目录，默认 `results` |

> 命令行走的是**整图自动检测 + 环形中值局部背景**那一套（方法学第 9 节），
> 与界面里的 ROI 定量口径不同，导出的 CSV 里 `origin` 列固定为 `local_background`。
> 需要论文级定量请用界面的 ROI 路径。命令行也没有 ROI 自检、没有双条带策略、
> 没有「每道条带数」。

## CSV 字段

### 条带结果 `*_bands.csv`

| 字段 | 含义 |
| --- | --- |
| `lane` / `band` | 泳道编号 / 该泳道内的条带编号（图上标作 L2-B1） |
| `x`, `y`, `width`, `height` | 包围框（像素）。`width` 是收紧后的条带横向足迹宽度，不是整条泳道宽 |
| `area` | 包围框像素数 |
| `mean_intensity` | 框内平均原始灰度（未扣背景） |
| `background` | 背景估计（ROI 路径为该段基线的每像素均值，折算回显示灰度） |
| `integrated_density` | 扣背景与噪声地板后的积分灰度，单位"灰度×像素"（越大信号越强） |
| `saturated_fraction` | 疑似饱和像素占比，≥ 0.05 即不可用 |
| `detection_limit` | 3σ 检出限，与 `integrated_density` 同单位；`0` 表示噪声估不出来、未评估 |
| `snr` | 信噪比 = `integrated_density ÷ (σ × √样本数)` |
| `below_detection` | `1` 表示 `snr < 3`，该积分与空白泳道无法区分（详见方法学第 10 节）。**注意它是噪声限，不是"这道有没有蛋白"** |
| `origin` | 这批数字用的背景口径：`roi_baseline`（ROI 基线）/ `local_background`（环形中值）/ `unknown`（调用方没说）。两套口径不可互相比较，详见方法学第 9 节 |

字段顺序即文件里的列顺序。同一目录下重复导出会覆盖同名文件，界面会先问一次。

### 内参 / 归一化

- **内参 CSV**：`kind,name,group,lane,integrated_density,background,mean_intensity,source,origin,band_pick,bands_used`，可供下次导入复用。导入时**按 `lane` 列认泳道**，不看行序——在 Excel 里排过序、或中间缺一个泳道，都不会把数值挪到别的泳道上。`origin` 同上表；`band_pick` 是该蛋白的条带策略（`all` / `top` / `bottom`，见方法学第 8 节），`bands_used` 是该泳道实际计入的条带号（多条用 `;` 分隔）。没有这三列的旧文件导入后口径记为 `unknown`、策略记为 `all`；CSV 里只有聚合值、没有逐条带明细，**导入的记录不能再改条带策略**，要改得重新定量。
- **归一化 CSV**：`group,lane,loading_control_name,loading_control,target_name,target,normalized,fold_change,loading_control_origin,loading_control_band_pick,loading_control_bands,target_origin,target_band_pick,target_bands,note`（`normalized = Target ÷ LC`；`fold_change` 相对对照泳道，对照泳道 = 1.0）。没配上的泳道该列为空，`note` 说明为什么空（缺泳道 / 背景口径不一致 / 低于检出限 / 内参强度为 0）。前 8 列的位置与旧版一致，新列一律追加在后面。
