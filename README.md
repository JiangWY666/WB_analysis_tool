# WB 灰度统计工具

面向 Windows 的 Western Blot（WB）条带灰度分析工具。由 PySide6 桌面界面与原生位深定量核心构成：16 位 TIFF 不降位深直接定量，ROI 泳道划分、强度剖面质控、内参归一化与 fold change 在同一界面内完成，导出的展示图附带一份可直接引用于方法学的处理记录。

> 结果应由实验人员复核。曝光饱和、噪声较强或背景高度不均匀的图像可能需要调整参数、旋转，或改用 ROI 半自动路径。本工具能够判定与无法判定的内容详见「已知限制」一节，**使用前应完整阅读该节**。

## 适用范围

**适用对象为线性响应的化学发光 / 荧光成像**——ChemiDoc、Amersham ImageQuant、Odyssey 等 CCD/CMOS 成像仪导出的 TIFF。此类设备的像素值与光子数近似成正比，因此对扣除背景后的像素值直接累加所得的积分灰度与蛋白量成正比。

**X 光胶片的扫描图不在适用范围内。** 胶片的响应为对数关系（光密度 OD 与曝光量成对数关系），直接做线性积分会系统性压缩浓度差：真实的 2 倍梯度被读作约 1.58 倍，梯度越大压缩越强。胶片图的定量须先将扫描灰度转换为光密度（OD 变换，依赖扫描仪的标定曲线或阶梯楔），本工具**不提供**该步骤。

其余前提条件：

- 比较限于同一张膜、同一次曝光之内。跨曝光、跨膜的绝对值不具可比性，仅归一化后的比值可比。
- 条带不得饱和。饱和像素占比 ≥ 5% 的条带会在结果表标橙、标注框转橙，该条数据不可用，应降低曝光重新采集。
- 图像不得经过任何非线性后处理（亮度、对比度、伽马、自动色阶）。应使用成像仪导出的原始 TIFF。

## 功能

- **深色桌面界面**（PySide6）：图像画布支持滚轮缩放、拖拽平移、适应窗口 / 1:1；右侧控制面板与底部剖面面板可停靠、可浮动、可隐藏
- **16 位 TIFF 原生支持**：加载与定量均在原始位深（8/16/32 位）上进行，显示层单独做 8 位映射，不损失定量精度；命令行与界面共用同一条通路
- **可调 ROI**：拖拽框选，8 向手柄改变尺寸、整体拖动改变位置；橙色泳道分隔线按剖面地形自动放置，支持拖动微调（可吸附至剖面谷底）、双击添加、右键删除、方向键 1 px 微调
- **双向同步剖面面板**（pyqtgraph）：ROI 列强度剖面与画布实时联动，分隔线在画布与剖面图中均可拖动；定量后可逐泳道查看剖面、基线与积分区间
- **两条摆正路径**：**标尺对齐**沿条带方向拖一条线后一键旋正；**自动测倾角**在 ROI 内测出建议角度（精度 0.02° 量级）并绘制参考线。该功能仅给出建议、不自动旋转，因为它无法判定自身何时被误导（方法学第 14 节）
- **ROI 定量**（推荐路径）：ImageJ 式逐泳道基线扣除、噪声地板扣除与条带横向足迹收紧；另提供整图自动检测与补画条带作为兜底
- **每道条带数**：纵向叠加的双条带在自动判据无法切分时，可指定"每道 2 条"强制切分，与「期望泳道数」对称
- **ROI 质量自检**：每次定量自动检查 ROI 绘制是否合规，结论显示于画布上方的诊断条，并在画布上标出建议的调整方向（方法学第 12 节）
- **结果表**：逐条带的位置、平均灰度、背景、积分灰度、饱和占比、信噪比；低于检出限（S/N < 3）的条带压暗显示，选中行高亮对应条带，误检条带可删除。默认显示 5 列，其余列可在界面设置中开启
- **归一化与 fold change**：内参（Loading Control）与目标蛋白**按泳道号**配对；双条带可按位置选取上 / 下条带；背景口径随数值传递，跨口径配对被拒绝；历史可导出 / 导入 CSV 复用
- **发表级导出**：从原始数据出发，分层导出 16 位无损干净版与 8 位标注版，写入 dpi 元数据，并附一份记录全部处理步骤的旁注说明文件（方法学第 15 节）
- **界面可调且持久化**：字体大小、画布标注线宽、结果表列显示在「视图 → 界面设置…」（`Ctrl+,`）中调整；面板可显隐，布局可一键重置
- **异步与可撤销**：加载、旋转、剖面、定量在后台线程执行，界面不阻塞；删除、清除 ROI、旋转、切换定量路径均支持 `Ctrl+Z` 撤销、`Ctrl+Y` 重做

## 方法学

本节记录各项定量口径及其实测依据，可作为回答审稿人质询的材料。阈值常量定义于 `wb_analyzer/quant.py`、`wb_analyzer/roi.py`、`wb_analyzer/roi_check.py`、`wb_analyzer/tilt.py` 顶部。

### 1. 位深与白电平

定量在 `BlotImage.raw`（float32，原生取值范围）上进行，8 位显示层仅用于预览与粗检测。

`white_level` 为**传感器满量程**，由数据推断而非取容器上限（`imageio._infer_white_level`）：uint8 取 255；uint16 吸附到 255 / 1023 / 4095 / 16383 / 65535 中能容纳实际峰值的最小一档。多数成像仪将 10/12/14 位读数写入 16 位 TIFF，若按 65535 计算，已削顶的条带会被报告为 0% 饱和，极性判别亦随之出错。TIFF 头中的 `SMaxSampleValue`（tag 341）若存在则优先采用，但取值不会小于实际最大值，以防错误标签裁掉真实数据。

### 2. 条带极性（深带 / 浅带）

`quant.resolve_dark_bands_native`：条带只会落在强度分布的某一侧尾部，因此比较 `median − P0.5` 与 `P99.5 − median`，某一侧长出 1.5 倍即判定为该侧。该判据与绝对量程无关。仅当两侧尾长相当（无对比度的空白帧）时才退回边框中位调判别。极性亦可在界面上手动指定。

### 3. 条带足迹收紧（tight，默认开启）

泳道条为相邻分隔线之间的整条竖带，而条带本身通常只占其中一部分，两侧空白会稀释积分。因此先定位条带的实际横向足迹（`_tight_band_span`）：

1. 在整条泳道的全宽纵向剖面上先分一次条带，得到条带所在的 y 区间；
2. **仅在这些条带行**（每段上下各留半个段高的余量）上求列平均剖面。ROI 显著高于条带时，空白行会稀释对比度，使弱带被误判为不可靠；
3. **背景电平实测，不依赖"泳道内总有空白列"这一假设**（`_strip_background`）：取条带段**之外的行**的中位数作为背景，与列剖面自身的 5 百分位取更低者作为 floor。原实现仅用 5 百分位，隐含假设"泳道至少 5% 的列为空白"；条带占满泳道时该假设不成立，5 百分位落在条带自身的平台上，相对切点从高于弱带的电平起算，整条弱带被判在阈值以下而切除。真实样图上的表现为：一条 250 px 宽的泳道只收到右侧 86 px、积分少计 48%，且 ROI 左边缘移动 3 px 即可在"正确"与"漏一条带"之间跳变。条带段之外的行对**每一列**都是背景，与条带横向宽度无关，因此该估计不会随泳道被占满而失效；
4. 以最强列为锚点向两侧扩展，直至信号跌破 `floor + 8% × 峰高`（`TIGHT_EDGE_FRAC = 0.08`）；
5. 峰高不显著（≤ 4σ，σ 由列剖面残差的 MAD 估计）时判定为未找到可靠条带，**退回整条泳道全宽**；宽度不足 5 px 时向两侧补齐（`TIGHT_MIN_WIDTH`）；条带行已覆盖 ROI 高度 70% 以上（`TIGHT_ROW_COVERAGE`）说明无空白可排除，列剖面仍使用全部行。

关闭 tight（`quantify_lanes(..., tight=False)`）即恢复为整条泳道全宽积分。

### 4. 基线扣除：rubber band 下凸包

足迹内逐行求和得到纵向剖面 `profile`，默认基线为 **rubber band**（`quant.rubber_band_baseline`），即剖面的**下凸包**：先做半径 n/100 的滑动平均，在候选点上求下凸包顶点，再线性插值成整条基线。

凸包只需一个坏点即可把整条弦拉到真实背景以下，因此候选点中先剔除"离群下陷"：以宽度 `min(max(3, n/20), 31)` 的滑动中值给出邻域水平，样本低于邻域 `max(6σ, 5% × 条带幅度)` 即判为离群（σ = 相邻差分的 MAD，`1.4826 × median(|Δ|) / √2`），并连同其前后各 radius 个样本一并排除。实测中一道 3 像素划痕可使邻近条带的积分增至三倍，该步骤即针对此类情形；剖面干净时结果与朴素橡皮筋逐位相同。

另提供 `valley`（谷–谷折线，局部极小值连线，同样排除离群点）与 `none`（不扣背景）两种模式。

扣除后得到**残差** `residual = profile − baseline`。绘制于剖面图、以及用于分段的是其截断版 `corrected = max(residual, 0)`；**积分使用未截断的 `residual`**，原因见下节。

### 5. 噪声地板扣除

修复前，空白泳道亦能积出正值，且数值随框高增大：n=400、σ=10 的纯噪声剖面积出 3610 ≈ 0.9·n·σ，**恒为正**。原因有二：

1. 橡皮筋为**下**包络，本身即低于背景均值（剖面越长，凸包可触及的低点越低），空白行的残差均值为正数 `d`；
2. `max(…, 0)` 截去全部负向涨落、只保留正向，额外贴上约 0.6σ。

误差因此正比于**参与积分的样本数**，与真实信号量无关——同一条带，ROI 高度增加会使积分值上升。

两项原因分别处理：

- **截断偏置不再产生**。积分对 `residual` 求和，不对 `corrected` 求和。空白处的正负涨落自行抵消，无需事后估计再扣除。条带内部信号远离 0，截断与否结果相同，故对真实条带无影响。
- **基线偏置 `noise_floor` 实测后扣除**（`quant._lane_noise`）：
  - **空白行**定义为所有条带段之外的行，每段上下再各留半个段高的缓冲（段在 4% 峰高处切分，紧邻的行仍带有条带的纵向拖尾）。缓冲不会为凑足样本而缩小：ROI 紧贴条带、空白行不足 12 个（`MIN_NOISE_SAMPLES`）时地板取 0，即不作扣除，而不以条带自身的拖尾充当噪声（实测后者会削去强带 5%）；
  - **`noise_floor`** 为空白行上 **`residual`（未截断）** 的均值，即上文的 `d`。**不取 `corrected` 的均值**：后者含有截断附加的 0.6σ，而条带内部并未被截断，以其扣除条带会多扣两到三倍；
  - 上限为 `3 × noise_sigma`（`FLOOR_SIGMA_CAP`），并钳至非负。该上限既阻止"分段漏掉的拖尾 / 拖影被当作噪声"，也使无噪声图恰好得 0；
  - **噪声尺度 `noise_sigma`** 为各段连续空白区内**相邻差分的 MAD**（`1.4826 × median(|Δ|) / √2`）。采用差分而非整体 MAD，是为了不受剖面自身形状影响，也不会在近乎恒定的空白泳道上塌缩为 0。

于是每个积分为「窗口内 `residual` 求和 − 样本数 × `noise_floor`」，结果再截至 ≥ 0（灰度积分为负无物理意义，真正为零的条带由检出限标记说明）。**噪声为 0 的图像（合成图、无噪声渲染）地板恰好为 0，数值与修复前逐位相同。**

分段阈值亦相应改为噪声感知（`SEGMENT_MIN_SNR = 4`）：空白水平之上不足 4σ 的"峰"不再切分为条带，否则纯噪声泳道会被切出大量假条带，并污染上述空白行估计。

实测（合成弱带 深 300 / 噪声 60，8 个噪声实现取平均，真值比 0.0075）：

| ROI 高度 | 60 | 200 | 500 | 三档波动 |
| --- | --- | --- | --- | --- |
| 修复前 | 0.00817 | 0.01022 | 0.01329 | **+62.6%** |
| 修复后 | 0.00758 | 0.00729 | 0.00746 | **+3.9%** |

纯噪声泳道（400 行）：积分 131,193 → **0**，并标记为低于检出限。

环形中值路径（自动检测 / 无 ROI 补画，见第 9 节）存在同类截断偏置，但形式更简单：背景取环的**中值**，恰落在噪声中心，故截断残留为 `σ/√(2π) ≈ 0.399σ`，按框内像素数扣除，σ 取环上像素的 MAD。

> **尚未解决：橡皮筋的两个端点构成"背景位置"的全部依据。** 凸包只能锚定于 ROI 的上下两端，且只能是**凸**的，无法跟随缓慢弯曲的背景。因此决定误差的**不是 ROI 的高度，而是上下边是否落在与条带同一片平整背景上**——这是一个**台阶**，而非随高度连续变差的漂移。
>
> 真实化学发光图（10 泳道、每道一对双带）实测：该膜为剪下的窄条，仅 y 336–426 这 90 行有膜，框外为相机暗电平（读数 1.7）。
>
> - **误差随 ROI 高度的变化并非渐变。** 上下边均留在膜内时，顶边取 338–344、底边取 406–426 之间任意组合（高度 62–88，相差 2 倍），最大泳道误差始终 ≤ 3.6%。
> - **一旦越过膜边缘，基线弦即落至膜外暗电平，误差呈阶跃式跳升。** 整块膜的本底连同拖尾被计入蛋白量：**最强泳道的总积分虚高 60%，相对定量最大误差 38%**。
>
> 该效应与上文的截断偏置性质不同（噪声地板只改变 ≤1%），根治需改用"每段两侧就近取局部背景"的基线模型。**在此之前**：ROI 的上下边须留在膜上（绘制规程见第 11 节，定量后软件会自检一遍，见第 12 节），且同一批相互比较的图像应保持同一高度。

### 6. 条带分段与积分

`quant.segment_bands` 在 `corrected` 上执行（先做 n/120 平滑）：

- 高于 `4% × 该泳道峰高`（`min_height_frac = 0.04`）且长度 ≥ 3 px 的连续段为候选条带；
- 段内相邻两峰之间的谷，满足下列**任一条件**即切开；
- 每段边缘再收紧至信号跌破 `2% × 段内峰高`（`SEGMENT_EDGE_FRAC = 0.02`）。

切分判据为「几何 **或** 统计」的并联：

| 判据 | 条件 | 覆盖的情形 |
| --- | --- | --- |
| 几何 | 谷底 ≤ 较小峰的 70%（`valley_drop = 0.30`） | 可分辨的两条带 |
| 统计 | 谷底比较小峰低 ≥ 3σ（`SEGMENT_SPLIT_SIGMA = 3.0`）**且** ≤ 较小峰的 98%（`SEGMENT_SPLIT_MAX_RATIO = 0.98`） | 处于瑞利极限附近的重叠双带 |

**仅有几何判据不足的原因。** 30% 的谷深要求比瑞利判据更高的分辨率，重叠双带在几何上无法切开。真实样图（10 个泳道，每道一对双带，实测单带 FWHM 8.5–11.3 px、中心间距 11–14 px，`d/FWHM = 1.02–1.42`）上：两个峰**每道均被找到**，第二峰高出分段阈值 6.9–18.3 倍、高出空白水平 39.7–133.3σ，唯一未满足的是谷比——8 个泳道停在 0.81–0.96，未达 0.70，因此 20 条带仅检出 12 条。

**不能仅调小 `valley_drop` 的原因。** 将该批双带全部检出需放宽至 ≤ 0.036，合成弱带的假分裂率随之由 0.2% 升至 4.8%（更弱的条带由 1.7% 升至 20.7%），放宽 25 倍以上。统计判据改换维度：谷深不与峰高比较，而与**噪声**比较。同一批泳道的谷深实测为 4.6σ–23.7σ，`k = 3` 使最难的一道仍有 53% 余量（`k = 4` 仅剩 15%，`k = 6` 重新漏检 2 条）；98% 的相对上限则排除"统计上显著、物理上无意义"的一档——强带顶部 1.6% 的起伏可达 26σ，但并非两条带。实测该判据将该图由 12 条修正为 20 条且无过分裂，而弱带、平顶带与空白泳道的假分裂率与修复前**逐格相同**。

统计判据要求 `noise_sigma > 0`。收紧条带足迹的路径（`_vertical_segments`）按默认的 `noise_sigma = 0` 调用，此时不设该门槛，任何浅谷都会被判为无穷显著。

**积分灰度 `integrated_density` 为该段内 `residual` 的逐像素求和减去 `段长 × noise_floor`**（不除面积、不除宽度，单位为"灰度×像素"）。整条泳道未找到任何峰时，退回"整条泳道一条记录"——扣除地板后该记录约等于 0，并标记为低于检出限。

#### 每道条带数（`expected_bands`）

界面位于「调整」页，与「期望泳道数」严格对称（前者控制纵向切几条带，后者控制横向切几条泳道，`0 = 自动`）。给定 N 后**绕过上述两条判据**，改为"在段内按谷切至 N 段为止"。其行为边界如下：

- **切分位置的选择**：按谷相对较小峰的**下探深度**（`(较小峰 − 谷底) ÷ 较小峰`）排序，自最深者开始切分。采用相对深度而非绝对深度，可避免强带旁的浅凹陷盖过弱带旁的真实分裂。
- **只补足至 N，不拆散已分开的段**：所需刀数 = `N − 当前连续段数`。一条泳道已被**空白**分成 N 段或更多时刀数 ≤ 0，不作切分，各段原样保留——`expected_bands` 无法将隔着空白的两条带合并为一条。
- **同一连续段内为双向调节**：一段连续信号中有 3 个峰而填入 2 时，只切 1 刀、得到 2 条带（而非 3 条）。因此"只增不合"仅对**空白分开的段**成立，段内的峰数由该参数直接决定。
- **谷数不足时饱和**：可切的谷少于所需刀数时，有几个切几个，**不报错也不强行切分**。切分不足的泳道会在画布上方的诊断条中列出（"已要求每道 N 条带，但泳道 x 没切够"）。
- **不影响足迹定位**：足迹只关心哪些行有信号，与是否切开无关。
- 实测在 ROI 绘制正确、自动分段已给出正确条带数的一批图像上，**填与不填该参数结果逐位相同**。

膜上双带的间距小于自动判据的分辨能力时，该参数是唯一可靠的兜底手段，但它**不能替代正确绘制 ROI**，见第 12 节。

> **重叠双带的分配比例不可依赖。** 在谷底切一刀并非解卷积：两条带在谷两侧仍相互贡献侧翼，强带保留更多。合成图上注入 2.0 的真实比例，切分后量得约 2.3（偏高约 15%）。**分段回答的是"此处有几条带"，而非"各占多少"**——对重叠双带作定量比较时须注意这一点。

### 7. 饱和判定

`imageio.saturation_fraction`，margin = 0.5%：深带图统计 `像素 ≤ white_level × 0.005` 的占比，浅带图统计 `像素 ≥ white_level × 0.995` 的占比。单条带占比 ≥ 5% 即判为饱和，界面标橙并计数。**饱和条带的积分值一律偏低且无法校正**，应重新采集。

### 8. 归一化公式

1. 每个蛋白按**泳道号**聚合为一个值。一个泳道含多条带（双条带）时，该值由该蛋白自身的**条带策略**决定，见下节。
2. `normalized(lane) = target(lane) ÷ loading_control(lane)`，**按泳道号配对**，而非按列表下标。仅在一侧出现的泳道照常成行，值留空并注明原因，不会静默地将其后所有泳道错位到相邻泳道上。
3. `fold_change(lane) = normalized(lane) ÷ normalized(对照泳道)`，对照泳道恒为 1.0，可在界面上指定。
4. 内参强度为 0 的泳道 `normalized` 留空（不作分母）。
5. 目标或内参任一侧低于检出限的泳道照常计算比值，但会在警告栏列出、在结果行注明"低于检出限"——两个测不出的数相除得到的是算术结果，不是测量结果。
6. **配对双方必须属于同一套背景口径**（见下节）。

#### 双条带的条带策略

| 策略 | CSV 中的 `band_pick` | 采用的条带 |
| --- | --- | --- |
| 合并全部（默认） | `all` | 该泳道所有条带 `integrated_density` 之和 |
| 只取上面那条 | `top` | 图像坐标 y 最小的一条 |
| 只取下面那条 | `bottom` | y 最大的一条 |

- **按蛋白设置**，在「归一化」页历史表的"条带"列双击修改。内参取下条、目标取上条属于允许的组合。
- **按位置选取，不按强弱。** 双条带通常是同一蛋白的不同修饰形式，分子量位置比亮度稳定得多。
- **某泳道只检出一条带时，选上或选下均采用该条**（"只有一条"不等同于"不采用这条"）。界面会列出这些泳道并说明策略在其上未生效，以免策略被误认为已起作用，而实际上这些泳道并未被切成两条。
- **存在三条及以上时，"上面那条"即最靠上的一条**，不存在"上面两条求和"的中间状态。
- **未被采用的条带仍保留、仍显示**：结果表中标记"未采用"、积分灰度加删除线，画布上绘制为虚线框。这与"删除"是两种操作——删除才会使其彻底消失。
- **更改策略为重新聚合，无需重新定量**，也不要求图像仍处于打开状态（逐条带明细存于记录中）。唯一例外是自 CSV 导入的记录：其中只有聚合值，更改策略会明确报错并要求重新定量。
- 背景与平均灰度取**被采用条带**的均值；某泳道的采用条带**全部**低于检出限时，该泳道才判为低于检出限。删除误检条带后聚合值随之减小；整条泳道被删空时该泳道号留下空档。

### 9. 背景口径：`roi_baseline` 与 `local_background`

- **ROI 定量**（推荐）：上述第 3–6 步，橡皮筋基线 + 噪声地板。CSV 中记作 `roi_baseline`。
- **整图自动检测**与**无 ROI 时补画的条带**：环形中值局部背景（`quant.measure_box_native`）——取框外一圈（左右各 ¼ 框宽、上下各 ½ 框高）的中值作为背景，积分 = `Σ max(背景 − 像素, 0) − 0.399 σ_ring × 框内像素数`。CSV 中记作 `local_background`。

两者的数值口径不同，**不可放入同一次比较**。存在 ROI 时补画的条带自动采用 ROI 口径；若退回局部背景口径，状态栏会明确提示。界面上两条路径互斥：切换到另一条时，上一条留下的框 / ROI 会被清除（可 `Ctrl+Z` 撤回）。

**口径随数值传递。** 每条 `QuantEntry`（归一化历史中的一行）均携带自身的 `origin`，导出的 CSV 亦含该列，历史表中有"口径"列可查。归一化时的处理如下：

| 两侧口径 | 处理 |
| --- | --- |
| 相同 | 正常计算 |
| **均已知但不同** | **拒绝配对**：`normalized` 与 `fold_change` 留空、`note` 写入"背景口径不一致"，警告栏列出，界面上整行标红并在最左侧标记 ⛔。**两侧的原始测量值照常显示**——各自均正确，错误的只是二者之商 |
| 一侧已知、一侧未知 | 允许配对，但警告栏说明无法确认二者同源，比值仅供参考 |

采取拒绝而非警告是设计选择：警告可被关闭，而跨口径的比值偏离一个未知倍数，**不存在正确的解读方式**。"未知"（`unknown`）是真实的第三种状态，而非默认猜测——旧版 CSV 导入以及任何未声明口径的调用方均落入此类；若将其默认为某一套口径，恰会制造该字段所要防止的错误。同一文件中 `origin` 列前后不一致时，整个蛋白按"未知"处理并给出警告。

### 10. 检出限（LOD）与信噪比

积分窗口越宽，累积的随机噪声越多：逐样本噪声按平方根累加。因此每个条带各有自身的门槛：

```
detection_limit = 3 × noise_sigma × √(积分窗口的样本数)
snr             = integrated_density ÷ (noise_sigma × √(样本数))
```

`snr < 3`（等价于 `integrated_density < detection_limit`）的条带标记为**低于检出限**：其积分与空白泳道在统计上不可区分。样本数在 ROI 路径上为条带段的**行数**，在环形中值路径上为框内**像素数**；两条路径的 σ 分别取空白行差分 MAD 与环上像素 MAD。

**噪声无法估计时**（合成的无噪声图，或条带占满 ROI、无空白可用），`detection_limit` 记为 `0`，表示"未评估"，此时不对任何条带打标——工具不给出未曾作出的判断。

标记同时出现在四处：

| 位置 | 表现 |
| --- | --- |
| 结果表 | `S/N` 列；低于检出限的整行压暗，悬停说明原因，表头计数中单列"N 个低于检出限 ⚠" |
| 画布 | 条带框改用钢蓝色（正常红、饱和橙），悬停显示 S/N 与检出限 |
| CSV 导出 | `detection_limit` / `snr` / `below_detection` 三列（`below_detection` 为 0/1）；标注图中这些框亦为钢蓝色 |
| 归一化 | 加入历史时状态栏列出相关泳道；归一化结果行注明"低于检出限"，警告栏说明该比值不可信 |

**解读方式**：低于检出限**不等同于**"该泳道没有蛋白"，只等同于"在本次曝光下测不出"。相应处理是延长曝光或增加上样后重新采集，而不是引用该数值。亦不应将其视为 0 参与倍数变化计算，作为分母时尤其危险。

**反向命题同样不成立：`below_detection = False` 不等同于"该泳道有蛋白"。** 它是**噪声限**，衡量的是"该积分比随机涨落大多少"，不判断积分中是否混入膜背景。ROI 绘制错误时，一条肉眼完全空白的泳道同样可得到 S/N 8–37 的"条带"，软件不会指出其为空。详见「已知限制」。

> **旧版本数据需重新解读。** 引入噪声地板扣除之前，弱条带的数值中含有一份正比于 ROI 高度的背景残余，**偏高**。实测下降幅度（弱/强比值，ROI 越高降幅越大）：ROI 高 500 降 **44%**（0.01329 → 0.00746，真值 0.0075），ROI 高 200 降 **29%**，ROI 高 60 降 **7%**；纯噪声区域由六位数降至 0。强条带几乎不变：**−0.05% ~ −0.07%**；ROI 紧贴条带（高 60、空白不足以估计地板）时为 −2.6%，该变化来自分段口径改为噪声感知与积分不再截断，而非扣除地板。真实 16 位化学发光图 + 强条带这一日常路径上，逐泳道变化为 **0 ~ −0.3%**。旧版本得到的弱带数值应重新定量，不可与新数值混用。

### 11. ROI 绘制规程

橡皮筋基线**在 ROI 内部**构建，仅能锚定于 ROI 的上下两端。因此 ROI 上下边的位置，等价于向工具声明"此处为背景"。位置不当时，条带下方的弦会一路下沉至该错误电平，其间的全部内容——膜的本底辉光、拖尾、相邻行的条带——均被计入信号。

以下条款来自一次覆盖 8 张真实膜、1377 次 ROI 扫描、3344 次敏感度测量的调查。**条款按优先级排列，冲突时以序号在前者为准。**

#### 规程 1（强制）：ROI 的上下边须落在膜上

上下边须与条带处于同一片背景中，**不得越到膜外的扫描仪暗底**。操作方式：上下边分别自膜的上下边缘**向内收至少 8% 的膜高**。

实测代价（"敏感度"定义为 ROI 边缘移动 1 px 所引起的泳道读数变化百分比，数值越小越稳定）：

| ROI 上下边的位置 | 中位敏感度 |
| --- | --- |
| **向内收 12% 膜高** | **0.079 %/px** |
| 与膜边齐平 | 0.65 %/px |
| 越过膜边 | 0.88 %/px |

两者相差接近一个数量级：边落在膜内时，移动十余像素只引起千分之几的变化；一旦齐边或越界，每移动 1 px 读数即变化近 1%，此时 ROI 的位置本身成为误差的主要来源。第 5 节所述膜上，越过膜边的后果是最强泳道虚高 60%、相对定量最大误差 38%，而条带数看不出异常。

#### 规程 2：在规程 1 允许的范围内，上下各留半个条带高度的空白

留白供噪声地板与检出限估计使用：空白行不足 12 个（`MIN_NOISE_SAMPLES`）时 `noise_floor` 取 0、`noise_sigma` 退回整条剖面的差分估计，检出限会虚高数十倍（实测：高 80 的 ROI 检出限为 72，压至高 40 后为 3047）。

**本条常与规程 1 冲突，冲突时以规程 1 为准。** 该批膜的垂直高度实测仅 95–152 px，与条带自身的行跨度基本同量级——"高度取条带跨度的 2 倍"在此类窄条膜上无法实现，强行满足即须越过膜边，相当于以 10%~50% 的误差换取检出限的准确度，代价不成比例。**膜高度充足时**（条带上下均有大片干净膜），2 倍是合适的目标：8 位单条带的 `pad4_001(1)_signal.tif`（8 泳道、条带行跨度 53 px）上，高度取 1.8–2.4 倍时最大泳道误差为 3.6%~4.8%，低于 1.2 倍时升至 8.6%~17%，高于 5 倍时升至 10% 以上。

#### 规程 3：分隔线置于两条带之间的空隙内，位置不限

**无须刻意置于正中。** 实测将分隔线在空隙内任意移动（n=178，含最宽 50 px 的空隙）：泳道积分误差 ≤ 1.9%，相邻泳道比值误差 ≤ 2.7%。且日常空隙的中位宽度仅 4 px、p75 仅 5 px，可移动范围本就有限。

真正关键的是**分隔线不得切入条带**——那会将一条条带的左右两半计入两个泳道，两个泳道的数值同时作废。软件会检查该项（第 12 节的判据 3），被列出的分隔线在画布上转为红色并加粗。

#### 规程 4：同一批相互比较的图像使用同一高度

余下的系统偏差在同高度的图像之间可大部分抵消；高度不一致时则不能。

#### 规程 5：自检报 error 时先修正 ROI，再读取数值

自检结论与分隔线敏感度的交叉表（3344 次测量）：

| 自检结论 | 分隔线敏感度中位 | 最大 |
| --- | --- | --- |
| 通过 | 0.245 %/px | 2.84 %/px |
| 报 error | 0.787 %/px | 15.64 %/px |

且**敏感度最差的 12 次测量全部被自检报为 error，零漏报**。因此顺序固定：先修正自检报出的 error，再读取表中的数值；在此之前调整分隔线或参数，均是在错误的基础上做微调。

#### 补充判据：宽空隙与无可见条带的泳道

某条空隙特别宽（> 40 px）、且相邻某个泳道肉眼看不到条带时，该泳道的积分**可能全部来自膜背景**。判据为：**将该条分隔线在空隙内移动 20 px，若该泳道读数变化超过一倍，则其不是条带。** 真实条带的读数不会因分隔线在空隙内小幅移动而翻倍（见规程 3 的 ≤1.9%）。

实测一张动态范围较大的膜（最弱带与最强带相差约 4 倍、强带周围存在一圈弥散辉光，其中一道肉眼看不到条带）上，ROI 绘制错误会使该空泳道虚增约 **25 倍**——其读数达到参考泳道的 29.8%，形态类似一条弱带；ROI 绘制正确后为 1.22%。该泳道在两种绘制方式下均为 `below_detection = False`，软件无法识别，详见「已知限制」。

### 12. ROI 质量自检

`wb_analyzer.roi_check.check_roi_quality(lanes, expected_bands=…)` 接收一次 ROI 定量的结果，输出结构化诊断：是否存在问题、属于哪一类、涉及哪些泳道 / 条带、应向哪个方向移动多少像素。界面在每次 ROI 定量后自动执行，结论显示在画布上方的诊断条中。

**自检仅诊断、不拒绝**，不修改任何数值——膜上只有一条窄带时，"绘制错误"也可能是唯一可行的绘制方式。确有理由如此绘制时可点击"我知道了"收起提示；ROI、每道条带数或问题本身发生变化后，提示会重新出现。

三条判据：

1. **条带数 = 泳道数 × 每道条带数。** 多出的条带即基线下沉后被误判为条带的背景。"每道条带数"未填写时取各泳道条带数的**众数**（并列时取较小者），列出的是与众数不符的泳道。各泳道条带数本身离散度较大时，会附加说明"连每道几条都难说"——该分布本身即表明上下边多半未落在同一片平整背景上。
2. **每个条带框距 ROI 上下边至少半个条带高度。** 贴边说明该侧没有可锚定的背景。"条带高度"取**实际检出条带高度的中位数**，因此更换膜、放大倍率或分辨率均无需调整参数；留白不足半个条带高度报"警告"，不足四分之一报"严重"（后者往往已切掉部分条带）。上下边**分别报告**，措辞亦区分（形如"把 ROI 上边往上挪至少 5 px"）；画布上会在该边内侧绘出所需的留白（斜纹带），将边拖至斜纹空出即可。未检出条带的空泳道单独列出，不参与前两条的比对。
3. **条带的横向足迹未被泳道分界切断。** 前两条只考察纵向，不检查足迹的左右边界，因此"分隔线自条带中间穿过"对其完全不可见：条带数正常、上下留白充足、表中数值均为正数，但每条条带的信号被分成两半计入两个泳道。判据为几何三项的合取——足迹**窄**于半个泳道间距、**一侧顶死**在分界上（与相邻足迹的空隙 ≤ 0）、**另一侧仍有余量**（该项是"足迹确实收紧过"的证据）。三项缺一不可：只用"窄"准确率为 0.47（基础率 0.52），只用"顶死"准确率为 0.43（基础率 0.37），三项合取实测准确率为 0.83（1584 个真实 ROI、11087 条泳道）。一条分隔线两侧的足迹均紧贴该线、且至少一侧偏窄时，另行报出"分隔线切在条带里"（准确率 0.886），并将该线在画布上标红加粗——该缺陷一次影响两个泳道，需修正的是该分隔线而非某个泳道。

纵向的两条判据（判据 1、2）在真实样图的 1044 个 ROI 上**同时通过时最大泳道误差从未超过 5%，零漏报**；代价是有意偏保守，部分可接受的 ROI 亦会被拦下（将判据 2 的"半个条带高度"放宽可使误报减少四成，但 5%~6% 一档的漏报翻倍，因此未作此调整）。横向判据（判据 3）的覆盖情况显著较差，见「已知限制」第 1 条。

**填写「每道条带数」时增加一项对照。** 强制切分会使判据 1 成为同义反复——段数即按该数切出。因此自检会**重新执行一次自动分段**（同一批剖面，不强制切分）作为对照：自动分段给出 30 条而设定为每道 2 条时，直接报出"强制切分掩盖了分段异常"。即使填写正确也会保留一句提示，说明该条带数由强制切分得到，不能作为 ROI 绘制正确的证据。

> **`expected_bands` 不能替代正确绘制 ROI。** 它只决定切分刀数，不改变基线。**与直觉相反，指定该参数会掩盖分段异常**：一个明显过高的框，自动分段给出 30 条带、异常可见；填入"每道 2 条"后给出整 20 条带、形态完全正常，而最大泳道误差为 **34%**——判据 1 就此失效，仅剩判据 2、3 起作用。因此在 ROI 过高时使用该参数，风险高于不使用。该参数的适用场景是 ROI 已绘制正确、但双带间距过小、自动判据无法切开。

**自检不覆盖的情形**（以下几项仍须目视检查图像）：

- **ROI 边压在膜缘上、而条带距其较远。** 判据 2 测量的是条带框到 ROI 边的距离，不判断 ROI 边**下方**是否为平整背景。实测底边恰好落在膜下沿时两条判据均通过，最大泳道误差却达 **9.6%**。
- **每个泳道均多切一段。** 判据 1 依赖泳道之间的不一致；ROI 系统性地将相邻一行条带整体框入时，众数随之变为 3，该判据不再报警。
- **足迹整条退回泳道全宽的那一类横向缺陷**（约 85%，见「已知限制」）。
- **膜本身不平、曝光不匀、背景存在梯度**：判据只考察几何，不考察背景电平。
- **重叠双带的分配比例**（第 6 节末）与**饱和**（第 7 节）属于另外的问题，不在自检范围内。

### 13. 泳道分隔线的自动放置

`roi.separators_from_profile` 直接读取 ROI 列剖面的地形，而非等分：查找局部极值 → 持久性剪枝去除空白区噪声峰 → 计算每个谷相对两侧峰顶的下探深度 → 估计"一条泳道应含多少条带足迹" → **排除落在同一条条带两个鼓包之间的候选谷** → 在条带区内以动态规划挑选一组分隔线（目标 = 谷质量 + 足迹宽度偏离先验）→ 消除空白泳道 → 将落在大片空白中的分隔线移至空白正中。

两个设计要点：

- **约束对象是"泳道内含多少条带足迹"，而非泳道的几何宽度。** 泳道旁的空白量无关紧要，所含条带数才有影响——中间整段空白因此天然免罚，而两条泳道未切开时足迹为 2 个单位、代价超过 11，高于任何一条浅谷的质量代价。真实样图中相对深度仅 0.08 的那条真实分隔线即由此切出。
- **条带数按"条带宽度"计数，而非按幅度。** 谷深只界定一个两端可靠的区间（深于 0.40 必为两条带，浅于 0.05 必非两条带），区间内由归并半径（0.57 × 条带宽）判定。原实现按绝对幅度计数，ROI 上方多框十余行空白即可使两个浅肩峰消失，条带数由 8 降至 6、单位宽度虚高 34%，随之丢失 3 条分隔线。

填写「期望泳道数」后强制切出相应数量（位置仍由剖面决定）；地形证据不足时回退到等宽网格 + 谷位吸附。该逻辑在部分真实膜上仍会失效，见「已知限制」。

### 14. 自动测倾角

「调整」页的**自动测倾角**按钮（`wb_analyzer.tilt.estimate_tilt`）。

**原理**：将 ROI 按不同角度作垂直**错切**，取"每行的列平均"（行投影）。真正水平的角度上行投影的边缘最陡，因为同一条带的全部像素落入同一行。于是在一组候选角度上取行投影平方梯度和 `Σ(Δp)²` 的极大值点。±10° 范围内先按 0.5° 粗扫、再按 0.05° 细扫，最后作抛物线插值。采用错切而非真旋转，是因为错切不改变外形、无需扩展画布，因而不产生旋转留下的空角与假边缘。

**精度**：中位误差 **0.023°**、p90 **0.125°**，单次耗时约 **14 ms**。横向对比 Hough（RMS 1.76°）、结构张量（2.05°）、FFT 主方向（5.02°），本方法 RMS 0.107°，相差一个数量级。

**该方法无法自判失败，这一性质决定了它的使用方式。** 调查在 468 个 ROI 样本上测试了 5 种自检判据（峰突出度、方差判据一致性、行列一致性、三分块一致性、是否顶到搜索上限），好样本与坏样本的分布几乎完全重叠：严重的失败都是**自洽**的，全部子判据被同一条强直线一并误导，因而彼此一致。最佳标定规则的覆盖率仅 33%，假自信率仍有 3.9%。因此本模块不给出任何置信度评分。

无法拦截的两种失败：

- **贯穿全宽的淡划痕**（20% 对比度）：算法会锁定到划痕上，报出数度的错误角度，`reason_code` 仍为 `ok`（实测 p90 误差 7.43°）。
- **ROI 中框入了膜缘、胶带一类硬直线**：报出的是该边的角度，而非条带的角度。四边各内缩 4% 只能排除紧贴边缘的一小部分。

可以拦截的只有三条**事先可验证的工程约束**，它们不属于算法自省：

1. 没有 ROI —— 拒答（在整图上计算会锁定到扫描边框上）；
2. 裁切宽度 < 250 px —— 拒答（两端高差不足，角度杠杆不够；实测 <200 px 时 median 误差 0.23° / p90 1.34°，≥350 px 为 0.022° / 0.077°）；
3. 极值点顶到 ±10° 边界 —— 拒答，不返回边界值（倾斜超过 10° 应先用整 90° 旋转摆正）。

另有"选区内看不到条带结构"一档亦会拒答。拒答时状态栏说明原因，**此前手动测量的标尺值不受影响**。

**因此界面不自动旋转。** 测得的角度仅写入标尺位，并在画布上按该角度绘制一条虚线参考线；**须先确认该参考线与条带平行，再点击"旋正为水平"**。该确认步骤是本功能唯一的正确性保障，跳过它等同于接受一个未经复核的角度。ROI 应框在条带上，不要贴近膜缘。

旋转角输入框保留 2 位小数（0.01°），与自动测角及标尺测量的量级一致；左侧滑杆为 0.1° 一格的粗调。

### 15. 发表级导出：展示图与旁注说明

`Ctrl+Shift+E`。整条链路自 `blot.raw` 出发，**不经过屏幕预览的 8 位图**。

**灰度映射是唯一不可逆的步骤**，因此置于对话框顶部，且**两个版本各自选择**——以单一下拉控制两版必然导致其中一版不正确：

| 映射 | 作用 | 适用场景 |
| --- | --- | --- |
| 线性全量程（干净版默认） | 原始值 0 → 黑、传感器满量程 → 白 | 存档、定量凭据；不拉伸、不削波 |
| 自动对比度拉伸（标注版默认） | 第 0.05 / 99.85 百分位拉满 | 供人阅读；真实膜的数据常集中于量程顶部不足 1% 的区间内，8 位图按线性映射仅剩两百余个灰阶，屏幕上无法分辨条带 |
| 手动黑白点 | 由使用者指定两个原始灰度值 | 需要跨图统一映射时 |

其余处理均为无损或不执行：

- **干净版与标注版分层导出**：干净版无标注、可保持 16 位单通道；标注版叠加条带框、文字标签、ROI 框、泳道分隔线（可逐层勾选），固定为 8 位彩色——没有主流写库支持 16 位 RGB，因此明确声明而非静默降位深。标注版文件名自动添加 `_annotated` 后缀。
- **只写入无损容器**（TIFF / PNG）。TIFF 使用 LZW。JPEG 一律拒绝：实测其在真实膜上改动灰度 6–7 级，与真实的强度差异无法区分。
- **导出时自原图按 Lanczos-4 重新旋正一次**（画布上的图像为双线性，以保证拖动流畅）。Lanczos 会在边缘过冲，结果会被钳回源数据的取值范围。
- **写入 dpi 元数据**（TIFF 分辨率标签 / PNG pHYs）。
- **削波占比在输出图上实测**，而非按映射窗口计算：舍入同样会将像素压至两端，且影响大得多——真实 16 位膜上，0.05/99.85 百分位拉伸形式上仅排除 0.15% 的像素，实际却将 **41.8%** 的像素推至 255。落在同一极值上的像素之间不再可区分，与其成因无关，因此应报告的是实测值。

#### 旁注文件 `*_export_info.txt`

每张导出的图像旁会写入同名的 `_export_info.txt`，导出完成后自动弹出显示。该文件记录图像自原始数据到成图的全部处理：

| 段落 | 内容 |
| --- | --- |
| 源数据 | 存储位深、满量程（传感器白电平，非容器上限）、原始尺寸 |
| 几何 | 旋正角度 / 方向 / 插值方式；裁切区域（原图坐标）；**重采样：无** |
| 灰度映射 | 映射方式、黑点、白点（均为原始灰度值）、自动映射所用百分位、传递函数（线性，未做伽马 / 曲线 / 局部调整）、输出格式与压缩、**纯黑与纯白的削波占比** |

| **方法学建议写法** | 一段完整的中文表述，将上述内容组织为可直接引用于论文方法学的文字 |

该文件即"对这张图做了哪些处理"这一问题的答案。

#### 打印尺寸与 dpi

**本软件不做插值放大。** 像素数在采集时即已确定，dpi 是"这些像素印多宽"的结果：

```
dpi = 像素宽 ÷ 印刷宽度（英寸）
```

因此对话框中可填写的是**打印宽度**，旁边实时显示由此算出的 dpi——增加宽度即可见分辨率下降。以一条裁出 624 px 宽的膜为例：

- 印 **52.8 mm** 宽 = 300 dpi（多数期刊的下限）
- 印 **26.4 mm** 宽 = 600 dpi

需要更高分辨率时，只能**在成像环节解决**（更高分辨率扫描 / 更大放大倍率重新采集）。将 624 px 插值为 1248 px 不会增加任何信息量。

## 已知限制

以下为本轮调查已确认、当前版本**尚未修复**的问题。每条给出现象、量级、触发条件与规避方式。

### 定量与 ROI

**1. ROI 自检无法识别约 85% 的横向缺陷。**
判据 3 要求足迹"一侧顶死、另一侧仍有余量"，因为这是"该足迹确实收紧过"的证据。但足迹无法收紧时会**整条退回泳道全宽**，此类足迹**两侧均**贴着相邻足迹（实测 5378 条两侧均贴的足迹中，收紧过的为 0），判据因此不报警。ROI 粒度的召回率仅 **0.175**。干净 ROI 上的误报率为 4.1%；泳道条宽度高度不均的 ROI **必然**误报，因为"泳道间距"取的是相邻足迹中心距的中位数。

*规避方式*：自检通过不代表横向无问题，须对照画布确认每条分隔线是否落在空隙内。宽窄不均的膜上收到判据 3 的警告时，应先看图再判断是否处理。

**2. 重叠双带的分配比例不可依赖。**
谷底切一刀并非解卷积，两条带在谷两侧仍相互贡献侧翼。合成图注入真实比例 2.0，量得约 2.3（**偏高约 15%**）。触发条件：以同一泳道内双带的上/下比值作为结论。

*规避方式*：分段回答"有几条带"，不回答"各占多少"。比较上下两条带须改用能真正分开二者的方法（更长的胶、更小的孔径），或仅报告"存在两种形式"。

**3. 自动判据在 d/FWHM ≈ 1.0 时召回率仅 2.5%。**
两条带中心间距接近单带半高宽时，几何判据（谷深 30%）与统计判据（3σ）均无法满足，自动分段只给出一条。

*规避方式*：使用「每道条带数」强制切分。填写前须先确认 ROI 绘制正确（第 12 节）。

**4. 微笑凹陷深于约 50% 时，一条条带会被切成两条泳道。**
弯曲条带的列剖面上，一条带呈现两个鼓包、中间一个凹陷。实测（合成剖面）相对深度 ≤ 0.50 时分隔线放置完全正常；**≥ 0.57 时每条条带均从正中被劈开**，8 条条带切出 16 条泳道。真实膜上的微笑凹陷实测为 0.006~0.208，通常不到该阈值。

*规避方式*：泳道数明显翻倍时，填写「期望泳道数」；分隔线位置仍由剖面决定，仅数量被固定。

**5. 弱于最强带 12% 的条带不被计数，该泳道得不到分隔线。**
`BAND_LEVEL_FRAC = 0.12` 是"该列上存在条带"的全局电平，自剖面地板起算、占动态范围的比例。实测：弱/强 = 0.15 时 8 条泳道全部切开；**弱/强 ≤ 0.12 时该泳道的分隔线消失**（7 条变为 6 条）。即**同一 ROI 内动态范围超过约 8 倍**时，最弱的一道会被并入相邻泳道。

*规避方式*：填写「期望泳道数」强制切出应有的道数，再手动将分隔线拖至正确位置。

**6. 足迹总量在动态范围大的膜上仍虚高约一倍。**
同一全局电平（`BAND_LEVEL_FRAC`）之上的列数被作为"条带足迹总量"，强带两侧的裙边整片高于该电平，故足迹总量虚高约一倍。它**不再导致分隔线放错**（放置改用相对位置判据之后），但"一条泳道应有多宽"的先验随之变宽，**会排除合法的窄泳道**。

*规避方式*：窄泳道被吞并时，同样使用「期望泳道数」。

**7. 弱泳道上噪声地板会在 0 与 45–71/行之间翻转，造成 20–30% 的台阶跳变。**
空白行少于 12 个（`MIN_NOISE_SAMPLES`）时 `noise_floor` 取 0，达到 12 个则按实测值扣除。因此 ROI 高度或条带分段结果的微小变化，即可使同一条弱带的积分在"已扣地板"与"未扣地板"之间跳变一档。**该现象与 ROI 绘制是否正确无关，绘制正确亦无法消除。**

*规避方式*：同一批需比较的图像使用同一 ROI 高度（第 11 节规程 4）；弱带数值出现无法解释的台阶时，检查相关泳道的空白行数是否恰在 12 附近。

**8. 噪声地板在真实扫描图上只扣除一部分。**
相邻行之间存在相关性，由相邻差分估计的 σ 因此偏小，而 `noise_floor` 被 `3σ` 封顶（`FLOOR_SIGMA_CAP`）。实测一张化学发光膜：空白行高出基线 14–53 个单位，而 3σ 仅为 8–9，故只扣除了其中一部分。该行为是**有意偏向"少扣"**的——多扣会削去真实信号。

*规避方式*：该项不是日常路径的主要误差项（在该图上其占比远小于 ROI 边越界的影响），按第 11 节绘制 ROI 即可。

**9. `below_detection` 是噪声限，不是背景系统误差限。**
它只回答"该积分比随机涨落大多少"，不回答"积分中是否全部为膜背景"。实测一张动态范围较大的膜（最弱带与最强带相差约 4 倍、强带周围存在一圈弥散辉光）上，即使 ROI 绘制正确，一条实际为空的泳道，其 7 条"带"的 S/N 仍达 **8–37**、`below_detection = False`——**软件不会指出该泳道为空**。

*规避方式*：采用第 11 节末的补充判据（将分隔线在空隙内移动 20 px，读数变化超过一倍即非条带），并始终对照图像确认该泳道肉眼是否存在条带。

**10. `expected_bands` 不能将隔着空白的两条带合并为一条。**
刀数 = `N − 当前连续段数`，段数已 ≥ N 时不作切分。因此一条已被空白分成 3 段的泳道，填 2 仍为 3 条。（同一**连续段**内该参数是双向的，填 2 会将 3 个峰切成 2 条——见第 6 节。）

*规避方式*：多出的段通常是 ROI 绘制错误的症状，应修正 ROI，而非以该参数掩盖。

### 分隔线自动放置

**11. ROI 左右边多出 2 px 即可使自动放置返回空列表；390 种取景中仅个位数给出正确条带数，此类膜必须手动指定泳道数。**
实测一张 8 泳道的膜（正确结果应为 7 条分隔线）：ROI 的左右边恰好贴齐条带所在的列范围时给出正确的 7 条，而左右边只要各多出 **2 px**，`separators_from_profile` 即返回**空列表**（不给出任何分隔线）。同一张图上按 390 种取景扫描，落在正确条带数上的仅个位数，其余或给出 0~5 条，或在空白区中生成数十条。

*规避方式*：**填写「期望泳道数」**。填写后同一批取景全部稳定给出 7 条分隔线，位置仍由剖面决定。这也是遇到任何"分隔线位置异常"时的首选处理。

### 自动测倾角

**12. 该方法无法判定自身被误导。**
贯穿全宽的淡划痕（20% 对比度）会使其锁定到划痕上（p90 误差 7.43°）；ROI 中框入膜缘或胶带时，报出的是该边的角度。两种情况下 `reason_code` 均为 `ok`，与结果正确时完全一致。三条拒答约束（没有 ROI / 宽度 < 250 px / 顶到 ±10°）均为事先可验证的工程约束，无法拦截这两种失败。

*规避方式*：**核对画布上的虚线参考线**，确认其与条带平行后再旋正。ROI 应框在条带上，不要贴近膜缘或划痕。该步骤没有替代方案（详见第 14 节）。

### 导出

**13. 标注版只能是 8 位彩色。**
彩色标注需要 RGB，而没有主流写库能产出 16 位 RGB。软件的处理是明确报错而非静默降位深：干净版仍保持所选位深。

*规避方式*：需要 16 位存档时导出干净版，标注版另存一份 8 位文件。

**14. 旧接口 `export.export_figure` 不记录自身的处理过程。**
它自一张已渲染的 8 位图裁切导出，没有映射信息、没有旁注文件，传入有损后缀时会静默改写为 `.png`。

*规避方式*：任何用于发表的图像均应走 `Ctrl+Shift+E` / `export_presentation_figure`。

`Ctrl+W`，或工具栏中「打开」右侧的关闭按钮，亦可自「文件 → 关闭当前图片」进入。执行后回到空白工作区：图像、朝向、ROI 与分隔线、撤销 / 重做栈、剖面、结果与诊断全部清除。

**归一化历史不受影响。** 跨膜流程中，历史是连接不同膜的唯一载体，因此关闭图片不触碰它，可直接打开下一张膜继续累积。

存在尚未保存的成果时会先行确认，并按重要性列出：

1. 本图的 N 个条带尚未加入归一化历史（关闭后需重新定量）；
2. 本图的 N 个条带的定量结果尚未导出。

"尚未加入历史"排在前面：历史丢失后必须重新定量，而结果表重跑一次即可恢复。没有打开图像、或没有可丢失的成果时，该操作直接执行。后台任务运行期间该操作不可用。

### 标签的降级显示

画布上的条带标签与剖面图上的泳道标签均为固定屏幕尺寸，可用空间却随缩放、面板宽度与字号变化。两处采用同一套契约：**要么按规则完整呈现，要么整批隐藏，不显示"恰好放得下的那几个"**——标签一旦不规则地缺失，误读的代价高于读不到。

条带标签（画布）的降级顺序：

1. 完整文案 `L2-B1`，最多错开 2 行排布；
2. 放不下则退化为仅泳道号 `L2`，同样允许错行；
3. 仍放不下则整批隐藏，仅保留选中或悬停的条带（恢复完整文案）；
4. 选中项也无法排开时，仅保留鼠标当前指向的一个。

泳道标签（剖面图左图）的降级顺序：

1. 完整文案 `L3`，每道均标注；
2. 放不下则去掉 `L` 前缀，仅保留数字 `3`；
3. 仍放不下则按规则间隔标注（每 2、3、4、6、8、12 道标一个，取第一个排得开的间隔）；
4. 最稀的间隔仍排不开时整批隐藏。

相邻标签之间保留最小空白（泳道标签 5 设备像素，条带标签同行 3 设备像素、错行 3 设备像素）；避碰判据读取标签的实际外接矩形，而非由字体度量估算，以保证"算得开"与"画出来不重叠"一致。

### 标准操作流程

1. **打开图像**：`Ctrl+O`，或将文件拖入窗口（支持 8/16 位 TIF/TIFF、PNG、JPG、BMP）。
2. **摆正**。图像歪斜时使用 **标尺对齐**（`2`）沿条带方向拖一条线，点击"旋正为水平/垂直"；微调范围 ±45°，横竖颠倒应先用 **编辑 → 旋转 90°**。框好 ROI 后亦可使用「调整」页的 **自动测倾角**：它只写入角度并绘制一条虚线参考线，**确认参考线与条带平行后**再点击旋正（须人工确认的原因见方法学第 14 节）。ROI 与分隔线会随旋转自动重映射。
3. **框选 ROI**（`1`）。上下边须留在膜上、距膜缘内收 ≥ 8% 膜高（方法学第 11 节）；分隔线按剖面地形自动划分泳道。分隔线位置异常时，应先在「调整」页填写**期望泳道数**，其效果远优于逐条手动拖动。分隔线在画布与底部剖面图中均可拖动微调；「调整」模式（`4`）下支持双击添加、右键删除。
4. **查看诊断条**。框好 ROI 后会**自动定量**（微调分隔线亦会自动刷新），也可按 `Ctrl+R` 手动重跑。画布上方即为 ROI 自检结论：绿色"自检通过"为最常见结果；橙色"警告"与红色"严重"会给出具体动作（例如"把 ROI 上边往上挪至少 8 px"），点击"详情"查看全文。被点名的条带框右上角带有三角角标，ROI 相应边上会绘出所需的留白（斜纹带），被点名的分隔线转为红色并加粗。**应先按提示修正 ROI，再读取数值。** 确有理由如此绘制时点击"我知道了"。
5. **补漏与删除误检**。漏检使用 **补画条带**（`3`）补充；误检在结果表或画布上选中后按 `Delete` 删除（可撤销，批量删除算一步）。每道纵向叠加双条带而只切出一条时，将「调整」页的**每道条带数**填为 2。
6. **归一化**。在「归一化」页将内参与目标分别加入历史（选定类型 / 蛋白名 / 分组），同组按泳道号自动配对计算 normalized 与 fold change，并可指定对照泳道。双条带可在历史表"条带"列中选择"只取上面那条 / 只取下面那条"——该操作改变聚合方式，不重新定量。
7. **导出**。`Ctrl+E` 输出条带 CSV 与标注图；`Ctrl+Shift+E` 输出发表级展示图（先选择干净版/标注版、灰度映射、位深、打印宽度，导出后弹出旁注内容）。
8. **关闭或切换**。`Ctrl+W` 关闭当前图片，回到空白工作区；归一化历史保留，可直接打开下一张膜继续跨膜流程。

> 删除误检条带后，加入历史的强度为**剩余条带**的合计，并会记录泳道号；
> 整条泳道被删空时该泳道号留下空档，归一化中单独成行并注明"缺该泳道"。

```powershell

```

```powershell

wb-analyze .\example.tif -o .\results --sensitivity 0.8 --background dark_bands
```

支持 PNG、JPG、JPEG、BMP 与 TIFF。

### 命令行的位深通路

`wb-analyze` 与图形界面共用**同一条原生位深通路**：`cli.main` → `analysis.analyze_image` → `imageio.load_blot` 按原始位深读入 → 在 8 位显示层上做条带**检测**（CLAHE 与 Otsu 只接受 uint8）→ `quant.remeasure_native` 在未经缩放的 `raw` 平面上**复测**每一个框。CSV 中的每个数值均来自 raw 平面。

> **旧版本 CLI 的结果与当前版本不可比，需要重跑。** 旧实现使用 `cv2.IMREAD_COLOR` 读图，
> 会先将 16 位曝光压缩为 256 个灰阶再测量：绝对值相差约 257 倍，更重要的是量化至 256 级
> 之后弱条带的相对强度亦发生失真，因此**比值同样不可沿用**。凡使用旧版本 CLI 处理过的
> 16 位图像，均须以当前版本重新分析。8 位输入的旧结果不受影响。

## 命令行参数

| 参数 | 含义 |
| --- | --- |
| `--sensitivity` | 检测灵敏度。默认 `1.0`；数值越小越容易检出弱条带，越大越严格（内部钳制到 0.35–2.5） |
| `--kernel-size` | 背景校正形态学核（奇数）。省略时按图像尺寸自动估计 |
| `--background` | `auto` / `dark_bands`（深带浅底）/ `light_bands`（浅带深底） |
| `--output` / `-o` | 结果目录，默认 `results` |

> 命令行走的是**整图自动检测 + 环形中值局部背景**这一套（方法学第 9 节），
> 与界面的 ROI 定量口径不同，导出 CSV 中 `origin` 列固定为 `local_background`。
> 论文级定量应使用界面的 ROI 路径。命令行不提供 ROI 自检、双条带策略与
> 「每道条带数」。

## CSV 字段

### 条带结果 `*_bands.csv`

| 字段 | 含义 |
| --- | --- |
| `lane` / `band` | 泳道编号 / 该泳道内的条带编号（图上标作 L2-B1） |
| `x`, `y`, `width`, `height` | 包围框（像素）。`width` 为收紧后的条带横向足迹宽度，非整条泳道宽 |
| `area` | 包围框像素数 |
| `mean_intensity` | 框内平均原始灰度（未扣背景） |
| `background` | 背景估计（ROI 路径为该段基线的每像素均值，折算回显示灰度） |
| `integrated_density` | 扣除背景与噪声地板后的积分灰度，单位"灰度×像素"（数值越大信号越强） |
| `saturated_fraction` | 疑似饱和像素占比，≥ 0.05 即不可用 |
| `detection_limit` | 3σ 检出限，与 `integrated_density` 同单位；`0` 表示噪声无法估计、未评估 |
| `snr` | 信噪比 = `integrated_density ÷ (σ × √样本数)` |
| `below_detection` | `1` 表示 `snr < 3`，该积分与空白泳道不可区分（详见方法学第 10 节）。**它是噪声限，不判断该泳道是否有蛋白** |
| `origin` | 该批数值的背景口径：`roi_baseline`（ROI 基线）/ `local_background`（环形中值）/ `unknown`（调用方未声明）。两套口径不可相互比较，详见方法学第 9 节 |

字段顺序即文件中的列顺序。同一目录下重复导出会覆盖同名文件，界面会先行确认。

### 内参 / 归一化

- **内参 CSV**：`kind,name,group,lane,integrated_density,background,mean_intensity,source,origin,band_pick,bands_used`，可供下次导入复用。导入时**按 `lane` 列识别泳道**，不依赖行序——在 Excel 中排过序、或中间缺失某个泳道，均不会将数值移到其它泳道上。`origin` 同上表；`band_pick` 为该蛋白的条带策略（`all` / `top` / `bottom`，见方法学第 8 节），`bands_used` 为该泳道实际计入的条带号（多条以 `;` 分隔）。缺少这三列的旧文件导入后口径记为 `unknown`、策略记为 `all`；CSV 中只有聚合值、没有逐条带明细，**导入的记录不能再更改条带策略**，如需更改须重新定量。
- **归一化 CSV**：`group,lane,loading_control_name,loading_control,target_name,target,normalized,fold_change,loading_control_origin,loading_control_band_pick,loading_control_bands,target_origin,target_band_pick,target_bands,note`（`normalized = Target ÷ LC`；`fold_change` 相对对照泳道，对照泳道 = 1.0）。未配对的泳道该列为空，`note` 说明原因（缺泳道 / 背景口径不一致 / 低于检出限 / 内参强度为 0）。前 8 列的位置与旧版一致，新列一律追加在其后。

核心模块（纯算法层，不依赖任何 GUI 框架）：

| 模块 | 职责 |
| --- | --- |
| `wb_analyzer/imageio.py` | 原生位深加载（`BlotImage`）、白电平推断、饱和占比、显示映射（`DisplayMapping`）、旋转与坐标重映射 |
| `wb_analyzer/quant.py` | 泳道定量核心：条带足迹收紧、rubber band 基线、噪声地板、条带分段（含 `expected_bands`）、检出限、原生位深测量 / 复测、标注 |
| `wb_analyzer/roi.py` | `RoiRect`、剖面分隔线放置（地形 + 动态规划）、旋转与角度工具 |
| `wb_analyzer/roi_check.py` | ROI 质量自检：条带数 / 上下留白 / 横向足迹三条判据，强制切分对照 |
| `wb_analyzer/tilt.py` | 自动测倾角（行投影平方梯度锐度最大化）与三条拒答约束 |
| `wb_analyzer/analysis.py` | 整图自动检测（8 位粗检）与 `analyze_image` 两段式流水线、`BandMeasurement` |
| `wb_analyzer/normalize.py` | 内参历史（带泳道身份）、背景口径与双条带策略、按泳道配对的归一化与 fold change、CSV 导入导出 |
| `wb_analyzer/export.py` | 条带 CSV、标注预览图、发表级展示图与旁注说明文件、打印尺寸换算 |
| `wb_analyzer/cli.py` | `wb-analyze` 命令行入口 |

打包与 CI：

- `desktop/run_gui.py` + `desktop/wb-analyzer.spec` + `scripts/build_windows.ps1`：Windows 打包（spec 中排除了 QtWebEngine / QtQuick / QtQml / tkinter / matplotlib 等大件，并按名称剔除随插件依赖链引入的 Qt DLL）
- `.github/workflows/build-windows.yml`：测试门禁（3.10 / 3.12 / 3.13）→ 打包 → **产物启动冒烟**（实际运行 exe，存活 20 秒且无致命日志才算通过）→ 打 tag 后自动发布 Release

界面对核心层的调用集中在 `wb_analyzer/ui/main_window.py` 顶部的若干自由函数中，一律按核心函数的真实签名直接调用：签名不匹配时当场抛出异常，而不是退回另一套口径、产生一个表面正常的错误数值。
